# repo uses the SAME filename as the other three (i18n-allow.txt) and both
# consumers read ONE list.
#
# Previously there were two files with different semantics — the pipeline's
# matched by SUBSTRING, this gate's by WHOLE VALUE — which is why one could
# call 5,253 values intentionally-English while the other flagged them.  Every
# folded-in rule was converted to whole-value form, which is what the old
# file's own header always asked for ("anchor with ^ / $"); they were written
# unanchored only because a comment-stripping bug meant none of them compiled,
# so nobody ever saw them behave.
#
# Whole-value is strictly TIGHTER: it exempts "this value IS a path / acronym /
# product name", never "this sentence happens to mention one".

# i18n "intentionally English" allow-list — the escape hatch for the strict
# gate in scripts/i18n_strict.py (mirrors sysmanage-docs/assets/locales/
# no-translate.txt, which predates it).
#
# A value listed here may stay byte-identical to English in every locale
# without failing `make lint`.  Use it for things that genuinely do not
# translate: product and vendor names, CLI invocations, protocol tokens,
# file paths, format strings that are pure interpolation.
#
# One rule per line:
#   some.dotted.key        exact dotted key (JSON) or exact msgid (.po)
#   settings.*.command     fnmatch glob on the key
#   re:<regex>             regex matched against the ENGLISH value
# Full-line comments start with '#'.
#
# Keep rules TIGHT.  A broad glob silently re-opens the hole this gate exists
# to close — prefer three exact keys over one wildcard that also swallows the
# prose next to them.  Anchor value regexes with ^ and $.

# NOTE: this is NOT assets/locales/no-translate.txt.  That file feeds the
# translation pipeline and matches by SUBSTRING; rules here are WHOLE-VALUE
# (fullmatch).  Keeping them separate is deliberate — a substring rule such as
# "value contains a URL" wrongly exempts any sentence that mentions one.
