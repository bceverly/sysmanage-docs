Snap Store Proxy & Offline Snap Content

Extend the content-distribution pipeline to Ubuntu snaps. Your fleet consumes snaps from a curated, versioned, offline-capable internal source — including fully air-gapped networks — instead of each host reaching out to snapcraft.io.

Overview

The compiled snap_proxy_engine Enterprise module extends SysManage's content-distribution pipeline to Ubuntu snaps. A fleet can consume snaps from a curated, versioned, offline-capable internal source rather than every host reaching snapcraft.io directly — which matters most on networks that are metered, locked down, or fully air-gapped. This brings the same curated-and-offline snap distribution as a Landscape snap proxy, delivered as an Enterprise-gated capability that rides SysManage's existing mirroring and content-lifecycle substrate.

Track Snaps

On a mirror (Settings → Repository Mirroring) you track the snaps you want to curate by name + channel — for example firefox on latest/stable. Each tracked snap carries a capture status that walks it through the pipeline: TRACKED → DISPATCHED → CAPTURED, or FAILED if a capture could not complete.

Capture

The Capture snaps action downloads each tracked snap together with its assertions — the signed metadata that snap ack needs to trust and install the snap offline — into the mirror tree. Capture is daemonless: it requires no running Snap Store Proxy service. Captured snaps are digest- and revision-pinned, so a curated version is exactly reproducible and never silently drifts.

Promote Through Content Views

Captured snaps materialize into an immutable content-view version alongside packages, so a single published version can carry both DEB/RPM content and the snaps your hosts need. From there they promote through Lifecycle Environments along the usual ordered path — Library → Dev → Test → Prod — and they ride the air-gap export ISO for free, with no extra step.

Serve & Repoint Hosts

A consuming host is repointed to install an environment's served snaps entirely offline: it pulls the snap bundle, runs snap ack on the captured assertions, and installs from the local content — no upstream store contact required, so it works on air-gapped networks. This is the Repoint snaps action on the content view's promotion lane, mirroring how package repoint works for DEB/RPM content.

Requirements

  • An Enterprise license with the snap_proxy_engine module loaded.
  • The mirror host needs snapd installed to capture snaps and their assertions.
  • Each consuming host needs snapd to snap ack the assertions and install the served snaps.
