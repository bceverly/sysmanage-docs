Built-in Host Metrics

Every host gets history for the numbers its agent already reports -- CPU, memory, swap, load and disk -- without anyone writing a script. Chart them on the host's Metrics tab, compare the busiest hosts on the Host Metrics page, and scrape them into Grafana through the same Prometheus endpoint as your custom metrics.

Overview

Custom metrics answer the questions only you can ask; built-in host metrics answer the ones every operator asks. The agent reports five host-level numbers on each periodic run, and the server keeps them as time series you can chart, compare across the fleet and alert on. They are stored as system-defined custom metrics, so retention, the samples API, the Prometheus endpoint and alert conditions all work on them exactly as they do on a metric you define yourself.

The Five Series

  • CPU usage (host.cpu_percent) -- average CPU use since the previous report, not an instantaneous reading.
  • Memory used (host.memory_used_percent) -- the percentage of physical memory in use.
  • Swap used (host.swap_used_percent) -- the percentage of swap in use. A host with no swap does not report this series at all.
  • Load average (1 minute) (host.load_1m) -- the one-minute load average, where the platform provides one.
  • Disk used (fullest filesystem) (host.disk_used_percent_max) -- the fullest local, writable, persistent filesystem. Read-only images, snap mounts and memory-backed filesystems are ignored, since they read 100% full by design.

A value the agent cannot read is left out, never sent as zero. A chart that shows zero means the host really reported zero.

The Host Metrics Tab

Open a host and choose the Metrics tab. Pick a range (the last 24 hours, 7 days, 30 days or 90 days) and click the series chips to choose which cards to show; the choice is remembered in your browser. Percent series are drawn on a fixed 0-100% scale so two hosts' charts can be compared at a glance.

  • Not reported -- the host sent no samples for that series in the range. The card stays on screen and says so rather than disappearing.
  • Turned off -- an administrator disabled collection of that series.
  • Gaps -- when a host was down or unreachable for more than 45 minutes, the line breaks instead of drawing a ramp across the outage.

The Fleet View

The Host Metrics page in the main navigation charts one series across the fleet: the busiest five or ten hosts, ranked by their average over the range, with their average and peak values in a table below the chart.

Above the chart, the page states how many hosts reported the series in the range, out of the whole fleet. When some hosts did not report it, the page says that they are not charted -- a fleet chart built only from the hosts that answered must not be read as the whole fleet.

Resolution and Storage

The agent reports about every five minutes. The server keeps one sample per series per host every 15 minutes, which is enough to see a trend or an incident without the table growing faster than a fleet can afford. At that resolution the five series take roughly 124 MB per day for every 1,000 hosts: about 3.7 GB at 30 days of retention and 11.2 GB at 90.

Built-in samples age out with the same retention window as custom metric samples, custom_metrics.retention_days (90 days by default). Samples are only stored while the observability engine is licensed and loaded, so an unlicensed server never quietly accumulates rows no one can view.

Managing the Built-in Series

The built-in series appear on the Custom Metrics page with a Built-in chip, targeting all hosts. They can be enabled or disabled there, and disabling one stops the server storing it. They cannot be edited or deleted, and their names are reserved: a custom metric cannot be created or renamed to host.cpu_percent or any other built-in name.

Prometheus and Grafana

The built-in series are published on the same GET /metrics/custom-metrics endpoint as custom metrics, as the sysmanage_custom_metric_value gauge with the series name in the metric label. A builtin label (true or false) separates them from your own metrics. The endpoint reports each host's latest sample, and leaves out a host whose last sample is too old to be current. No new scrape job is needed if you already scrape custom metrics; see the Custom Metrics guide for the scrape job and how to restrict access to the endpoint.

# Five busiest hosts by CPU, from the built-in series
topk(5, sysmanage_custom_metric_value{builtin="true", metric="host.cpu_percent"})

Requirements

  • Professional or Enterprise license with the observability engine.
  • An agent version that reports built-in host metrics. Older agents keep working; their hosts show as not reported.
  • The View Host Details role to view the charts.
