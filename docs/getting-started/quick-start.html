Quick Start Guide

Install the SysManage server from a native package, point it at PostgreSQL, give nginx a certificate, and open the console. About fifteen minutes on a fresh host.

Before You Begin

This guide installs the server from the package built for your platform. For the full platform matrix, build-from-source instructions, and per-distribution prerequisites, see the Server Installation guide.

  • PostgreSQL 12 or newer, on this host or a remote one. SysManage will not start without it.
  • A TLS certificate and private key for the server's hostname. nginx refuses to start without one — deliberately, because a management console must not come up in cleartext just because a certificate was missing.
  • Inbound 443 (plus 80 if you want the redirect). Nothing else needs opening: agents reach the server over outbound 443 and the backend stays on loopback behind nginx.
  • Root or sudo on the target host.
Tip: The package prints every step below as its post-install message, with the paths already filled in for your platform. If you lose it, it is in the package manager's log.

Installation

1

Install the Package

Download the package for your platform from the releases page and install it. Replace X.Y.Z with the release you are installing.

Debian / Ubuntu

VERSION=X.Y.Z
curl -LO https://github.com/bceverly/sysmanage/releases/download/v$VERSION/sysmanage_${VERSION}-1_all.deb
sudo dpkg -i sysmanage_${VERSION}-1_all.deb

# Pull in anything dpkg reported as missing
sudo apt-get install -f

RHEL / CentOS / Fedora

# Download the .rpm asset for your release from the releases page, then:
sudo dnf install ./sysmanage-*.rpm

Other platforms

openSUSE, Alpine, FreeBSD, OpenBSD, NetBSD, macOS and Windows packages are published on the same releases page. The steps that follow are identical on every platform; only the install command and the nginx configuration path differ, and the post-install message prints the right path for you.

2

Create the Database

To use a local PostgreSQL instance:

sudo apt-get install postgresql
sudo -u postgres createuser sysmanage
sudo -u postgres createdb sysmanage -O sysmanage
sudo -u postgres psql -c "ALTER USER sysmanage WITH PASSWORD 'your-password';"

A remote database works just as well — you will supply its host and credentials in the next step.

3

Write the Configuration

The server reads /etc/sysmanage.yaml. The configuration builder generates a complete file — database connection, hostname, TLS, authentication and logging — which is faster and less error-prone than writing it by hand.

sudo chmod 600 /etc/sysmanage.yaml

The file holds database credentials, so keep it readable only by root.

4

Run the Database Migrations

Check what is pending, then apply it. This migrates the control-plane schema and, if multi-tenancy is enabled, every tenant database as well.

cd /opt/sysmanage
sudo -u sysmanage .venv/bin/python scripts/sysmanage_migrate.py --status
sudo -u sysmanage .venv/bin/python scripts/sysmanage_migrate.py

With multi-tenancy enabled the per-tenant pass leases credentials from OpenBAO, so OpenBAO must be running when you migrate.

5

Install the TLS Certificate

Put your certificate and key where nginx expects them:

/etc/sysmanage/tls/server.crt
/etc/sysmanage/tls/server.key

Or point nginx somewhere else by editing these two lines in its configuration — the path varies by platform, and the post-install message prints yours:

ssl_certificate     /etc/sysmanage/tls/server.crt;
ssl_certificate_key /etc/sysmanage/tls/server.key;

If you do not have a certificate yet, certbot certonly --standalone -d your-server.example.com will obtain one; then point the two lines at that name's fullchain.pem and privkey.pem. Check the result before starting:

sudo nginx -t
Evaluating locally? Set dev_mode: true in /etc/sysmanage.yaml to skip nginx and TLS entirely. The server then serves the web interface on port 3000 and the API on 8080 over plain HTTP, binding every interface so agents elsewhere on your LAN can reach it. Never do this on a production host.
6

Start the Service

sudo systemctl start sysmanage
sudo systemctl status sysmanage

On the BSDs and other non-systemd platforms, use the service command the post-install message printed.

7

Open the Console

https://your-server.example.com/

The web interface and the API share this one origin. Log in with the administrator account from your configuration file — the user name is an email address.

Verify the Installation

1. The service is running

sudo systemctl status sysmanage

2. The API answers

curl https://your-server.example.com/api/health

# Database connectivity specifically:
curl https://your-server.example.com/api/health/db

3. The logs are clean

sudo tail -n 50 /var/log/sysmanage/*.log

If something is wrong

  • nginx will not start: almost always a missing or unreadable certificate. sudo nginx -t names the file it could not read.
  • The service starts then exits: check the database connection in /etc/sysmanage.yaml and confirm the migrations ran.
  • Login returns an error: the administrator user name must be a full email address, not a bare name.
  • Nothing listens on 443: confirm nginx is running and that no other service already holds the port.
