Your First Mixed Fleet in 30 Minutes

Install the free Community server, connect two machines running different operating systems -- Ubuntu and FreeBSD -- and manage them as one fleet: approve them, compare their inventory and updates, install a package on both, and find the record of it in the audit log.

Tested end to end on fresh virtual machines -- an Ubuntu 24.04 LTS server and a FreeBSD 14.5 host -- with SysManage server and agent 3.12.1.7. Every command and every expected result below comes from that run.

What you need

  • A server: Ubuntu 24.04 LTS with 2 CPUs, 4 GB of memory and 25 GB of disk, and a sudo account. The other two machines must reach it on port 443.
  • An Ubuntu host to manage. The server itself works fine as the first host, which is what this walkthrough does.
  • A FreeBSD 14 host with root access. To use Windows instead, install the agent with winget install --id sysmanage.sysmanage-agent --exact and follow the agent installation guide for its configuration file; the rest of the walkthrough is the same.
  • Internet access on all three, to download packages. Nothing needs to reach them from outside: agents connect out to the server.

1. Install the server

On the Ubuntu server, add the SysManage repository and install the server with PostgreSQL. The package installs nginx and OpenBAO (the secrets store) for you.

sudo add-apt-repository -y ppa:bceverly/sysmanage
sudo apt-get update
sudo apt-get install -y sysmanage postgresql

Expect: the install ends with "SysManage Server installation complete!" and a notice that a TLS certificate is required. You add one in step 3.

2. Create the database

Create a database and its user, and put the password into /etc/sysmanage.yaml. These commands generate a random password and write it there for you.

DBPASS=$(openssl rand -base64 18)
sudo -u postgres createuser sysmanage
sudo -u postgres createdb sysmanage -O sysmanage
sudo -u postgres psql -c "ALTER USER sysmanage WITH PASSWORD '$DBPASS';"
sudo sed -i "s|password: \"CHANGE_ME_IN_PRODUCTION\"|password: \"$DBPASS\"|" /etc/sysmanage.yaml

3. Give the server a certificate

SysManage serves everything on port 443 and will not start without a certificate. For an evaluation, a self-signed certificate is enough; the agents are told to trust it in steps 6 and 7. Use the address your hosts will reach the server by.

SERVER=$(hostname -I | awk '{print $1}')     # or the server's DNS name
sudo install -d -m 755 /etc/sysmanage/tls
sudo openssl req -x509 -newkey rsa:3072 -nodes -days 90 -subj "/CN=$SERVER" \
  -addext "subjectAltName=IP:$SERVER" \
  -keyout /etc/sysmanage/tls/server.key -out /etc/sysmanage/tls/server.crt
sudo chmod 600 /etc/sysmanage/tls/server.key
# A copy anyone can read, for the agents
sudo install -m 644 /etc/sysmanage/tls/server.crt /usr/local/share/ca-certificates/sysmanage-eval.crt

If the hosts reach the server by name, use subjectAltName=DNS:your.server.name instead. For production, use a certificate from your own certificate authority or Let's Encrypt, as described in the server installation guide.

4. Migrate the database and start

sudo sysmanage-migrate
sudo systemctl restart sysmanage
sudo nginx -t && sudo systemctl reload nginx
curl --cacert /usr/local/share/ca-certificates/sysmanage-eval.crt https://$SERVER/api/health/db

Expect: sysmanage-migrate ends with "[OK] Migrations complete.", nginx -t says the test is successful, and the health check answers {"status":"healthy","database":"up"}.

5. Sign in and create your administrator

The package generated a recovery account. Read it from the configuration file, then open https://<server>/ in a browser. Accept the certificate warning -- it is your own self-signed certificate.

sudo grep -E 'admin_(userid|password)' /etc/sysmanage.yaml

Sign in with that email address and password. A red banner says you are using the recovery account. Choose Create your administrator, enter your own email address and a password, then sign out and sign in as the new administrator. No email setup is needed. The recovery account is only for getting in; remove it from sysmanage.yaml when you go to production.

6. Connect the Ubuntu host

Install the agent and point it at the server. On a host other than the server, copy /usr/local/share/ca-certificates/sysmanage-eval.crt from the server to the same path first.

sudo add-apt-repository -y ppa:bceverly/sysmanage-agent
sudo apt-get update
sudo apt-get install -y sysmanage-agent
sudo sed -i "s|url: \"https://sysmanage.example.com\"|url: \"https://$SERVER\"\n  ca_bundle: \"/usr/local/share/ca-certificates/sysmanage-eval.crt\"|" /etc/sysmanage-agent.yaml
sudo systemctl restart sysmanage-agent
sudo grep -m1 "Connected to server successfully" /var/log/sysmanage-agent/agent.log

Expect: the last command prints a line ending in "Connected to server successfully" within about half a minute.

7. Connect the FreeBSD host

As root on the FreeBSD host, download the agent package and check its SHA-256 checksum against the published one -- the two lines must match. pkg install fetches the agent's dependencies from the FreeBSD repository. Copy sysmanage-eval.crt from the server first.

VERSION=$(fetch -qo - https://repo.sysmanage.org/agent/freebsd/latest.txt)
BASE=https://repo.sysmanage.org/agent/freebsd/packages/$VERSION
fetch "$BASE/sysmanage-agent-$VERSION.pkg" "$BASE/sysmanage-agent-$VERSION.pkg.sha256"
sha256 -q "sysmanage-agent-$VERSION.pkg"; cut -d' ' -f1 "sysmanage-agent-$VERSION.pkg.sha256"
pkg install -y "./sysmanage-agent-$VERSION.pkg"

mkdir -p /usr/local/etc/ssl
install -m 644 sysmanage-eval.crt /usr/local/etc/ssl/sysmanage-eval.crt
CONF=/usr/local/etc/sysmanage-agent/config.yaml
sed -i '' -e 's|url: "https://sysmanage.example.com"|url: "https://SERVER-ADDRESS"|' \
  -e 's|# ca_bundle: "/etc/ssl/certs/corporate-root.pem"|ca_bundle: "/usr/local/etc/ssl/sysmanage-eval.crt"|' "$CONF"
sysrc sysmanage_agent_enable=YES
service sysmanage_agent start
service sysmanage_agent status

Replace SERVER-ADDRESS with the server's address. Expect: "sysmanage_agent is running as pid ...", and "Connected to server successfully" in /var/log/sysmanage-agent/agent.log.

8. Approve both hosts

A new host waits for an administrator before it is managed. In the console, open Fleet > Hosts. Both hosts are listed as Approval Needed. Select them and choose Approve Selected. Within a minute both show Up, and each host's page fills in: operating system, kernel, hardware, software.

For more hosts than you want to approve by hand, a registration key approves hosts as they enroll; see Agent Setup and Approval.

9. See them side by side

  • Fleet > Hosts lists both, with platform, status and whether updates are pending.
  • Open each host: Info, Hardware and Software read the same on both. The Ubuntu host's software comes from apt and snap, the FreeBSD host's from pkg.
  • Patching > Updates lists every pending update across the fleet, security updates first, with the package manager for each. A freshly installed host may have none.

10. Install a package on both

On each host's page, open Software, choose Add Package, search for tree, choose Install next to it, then Install Selected Packages. The same steps run apt on Ubuntu and pkg on FreeBSD. Within a minute tree appears in each host's software list, and the request shows Completed under Software Changes.

11. Find it in the audit log

Open Security > Audit Log. Each approval ("Approved host ...") and each installation ("Queued installation of 1 packages on host ...") is there with who did it and when. Export it as CSV or PDF from the same page.

If something goes wrong

What you seeWhat to do
nginx -t: unknown directive "http2"A server package older than 3.12.1.7 on nginx older than 1.25. Upgrade the package, or in /etc/nginx/sites-available/sysmanage-nginx.conf delete the line http2 on; and change both listen ... 443 ssl; lines to listen ... 443 ssl http2;.
The agent log says certificate verify failedThe agent cannot trust the server's certificate. Check that ca_bundle points at the copy of server.crt, and that the address in url is the one in the certificate's subjectAltName (step 3).
A host never appears in the consoleFrom the host, run curl --cacert <the certificate> https://<server>/api/health. If it cannot connect, open port 443 on the server (sudo ufw allow 443/tcp) and check the address in the agent's url.
Approve Selected does nothing; the host stays Approval NeededYou are signed in as the recovery account, which cannot approve hosts. Create your administrator (step 5) and sign in as it.
FreeBSD: pkg add stops at "Missing dependency"Use pkg install -y ./sysmanage-agent-VERSION.pkg as in step 7: pkg add does not fetch dependencies from the FreeBSD repository.
http://<server>/ shows "Welcome to nginx!"Ubuntu's stock nginx site is answering port 80. Run sudo rm /etc/nginx/sites-enabled/default and sudo systemctl reload nginx; HTTP then redirects to SysManage over HTTPS.

Cleaning up

On Ubuntu: sudo apt-get purge sysmanage-agent sysmanage. On FreeBSD: service sysmanage_agent stop, then pkg delete sysmanage-agent. Delete the host from Fleet > Hosts if the server stays.
