Cross-Platform Support

What the agent does on each operating system: which package managers it reads, which updates it can find, and which of those it can install for you.

Overview

The same agent runs on every supported platform and reports to the server the same way. What differs is the package management underneath it. For each package manager the agent can do up to three things, and they are not always all available:

  • Inventory: list what is installed, for the Software tab and for vulnerability matching
  • Update detection: find available updates and show them on the Updates tab
  • Update apply and install: install those updates, or a new package, when you ask from the server

The agent detects which package managers are present on each host and reports only those. Installing the agent itself is covered in Agent Installation.

Package Management by Platform

"Detected only" means the agent shows the update but cannot apply it from the server; apply it on the host with the package manager itself.

Installing a new package from the server works with APT, DNF and YUM, zypper, pacman and Snap on Linux, pkg on FreeBSD, pkg_add on OpenBSD, pkgin on NetBSD, Homebrew on macOS, and winget and Chocolatey on Windows.

OpenBSD and NetBSD inventory is read with pkg_info. On OpenBSD the agent does not detect package updates; run pkg_add -u on the host. DragonFly BSD is not supported.

Linux Support

  • Service: sysmanage-agent, run by systemd, or by OpenRC on Alpine
  • Privileges: the packages run the agent as the unprivileged sysmanage-agent user, with a sudo allowlist for the commands it needs; see Privileged Execution
  • Security updates: APT and DNF updates are marked as security updates when the repository says so
  • Also reported: Ubuntu Pro status on Ubuntu, and container images when Podman, Docker or nerdctl is installed

BSD Support

  • FreeBSD: service sysmanage_agent (rc.d); package and release updates through pkg and freebsd-update
  • OpenBSD: service sysmanage_agent (rcctl); base-system errata through syspatch, and release upgrades through sysupgrade
  • NetBSD: service sysmanage_agent (rc.d); package updates from pkgin are shown, and applied on the host

macOS Support

  • Service: the com.sysmanage.agent launch daemon
  • Inventory: Homebrew formulae and casks, installed applications, and App Store applications. MacPorts packages are not inventoried.
  • Updates: Homebrew, MacPorts, App Store and macOS updates are shown; applying them from the server is not available on macOS yet. Packages can be installed with Homebrew.

Windows Support

  • Service: SysManageAgent
  • Inventory: installed programs from the registry, Microsoft Store apps, and winget packages. Chocolatey and Scoop packages are not inventoried.
  • Updates: Windows Update, winget, Chocolatey, Scoop and Microsoft Store updates are shown. Windows Update, feature upgrades, winget and Chocolatey updates can be applied from the server; Scoop and Store updates are detected only.

One Configuration File Everywhere

The configuration file has the same settings on every platform: /etc/sysmanage-agent.yaml on Linux, macOS and the BSDs, and C:\ProgramData\SysManage\sysmanage-agent.yaml on Windows. The agent finds the package managers on its own, so there is nothing platform-specific to set. See the Agent Configuration Guide.

server:
  url: "https://sysmanage.example.com"
  verify_ssl: true

collection:
  system_info_interval: 300      # seconds
  package_info_interval: 3600
  update_check_interval: 3600

Cross-Platform Troubleshooting

Package Manager Not Found

The agent looks for each package manager on its PATH. If one is missing from the inventory, check that the agent's service account can find and run it:

# Linux and the BSDs
which apt dnf yum zypper pacman apk snap flatpak pkg pkg_info pkgin

# macOS
which brew

# Windows (PowerShell)
Get-Command winget, choco, scoop -ErrorAction SilentlyContinue

Service Management Failures

sudo systemctl status sysmanage-agent                      # Linux (systemd)
sudo rc-service sysmanage-agent status                     # Alpine Linux
sudo launchctl list | grep sysmanage                       # macOS
Get-Service SysManageAgent                                  # Windows
sudo service sysmanage_agent status                        # FreeBSD, NetBSD
doas rcctl check sysmanage_agent                           # OpenBSD

See Agent Troubleshooting for connection, certificate and log problems.
