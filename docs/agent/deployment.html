Deploying the Agent to Many Hosts

Roll the agent out to a fleet from the same signed packages you would install by hand, deliver its configuration with your automation, and approve the hosts.

Deployment Overview

A fleet rollout is three steps on every host: install the agent package, write /etc/sysmanage-agent.yaml (or C:\ProgramData\SysManage\sysmanage-agent.yaml on Windows), and restart the agent. Then each host registers and waits for approval. Any configuration management tool can do the first three; the commands for each platform are on the Agent Installation page.

Package Managers

Install from the signed channel for each platform:

  • Launchpad PPA (Ubuntu)
  • SysManage APT repository (Debian)
  • Fedora Copr (RHEL family, Fedora, Amazon Linux)
  • SysManage RPM repositories (openSUSE Tumbleweed, SLES, EL9)
  • winget (Windows) and Homebrew (macOS)

Configuration Management

Drive those package managers from the tool you already use:

  • Ansible playbooks
  • Puppet manifests
  • Chef cookbooks
  • SaltStack states

Hosts SysManage Builds

Machines provisioned by SysManage itself, by PXE or from a cloud image, install the agent and enroll on their own. See the Provisioning Engine (Professional+).

SysManage does not publish container images; install the native package for your platform.

Ansible Deployment

This playbook installs the agent on Ubuntu, Debian, the RHEL family, openSUSE Tumbleweed and SLES 15 from the signed repositories, writes the configuration, and restarts the agent. It uses ansible.builtin modules and two from the community.general collection (copr and zypper_repository).

Playbook

---
- name: Deploy the SysManage agent
  hosts: all
  become: true
  vars:
    sysmanage_url: "https://sysmanage.example.com"
    # Optional: a registration key that approves hosts automatically
    # (Professional+ Enterprise). Keep it in Ansible Vault.
    sysmanage_registration_key: ""

  tasks:
    # Ubuntu: the Launchpad PPA
    - name: Add the SysManage agent PPA
      ansible.builtin.apt_repository:
        repo: ppa:bceverly/sysmanage-agent
      when: ansible_distribution == "Ubuntu"

    # Debian: the SysManage APT repository, verified against its key
    - name: Install the SysManage archive key
      ansible.builtin.get_url:
        url: https://repo.sysmanage.org/agent/sysmanage-archive-keyring.gpg
        dest: /usr/share/keyrings/sysmanage-archive-keyring.gpg
        mode: "0644"
      when: ansible_distribution == "Debian"

    - name: Add the SysManage APT repository
      ansible.builtin.apt_repository:
        repo: "deb [signed-by=/usr/share/keyrings/sysmanage-archive-keyring.gpg] https://repo.sysmanage.org/agent/deb stable main"
        filename: sysmanage-agent
      when: ansible_distribution == "Debian"

    - name: Install the agent (Ubuntu, Debian)
      ansible.builtin.apt:
        name: sysmanage-agent
        update_cache: true
      when: ansible_os_family == "Debian"

    # RHEL family, Fedora, Amazon Linux: Fedora Copr. RHEL-family hosts
    # need EPEL enabled first, as on the installation page.
    - name: Enable the SysManage agent Copr
      community.general.copr:
        name: bceverly/sysmanage-agent
      when: ansible_os_family == "RedHat"

    - name: Install the agent (RHEL family)
      ansible.builtin.dnf:
        name: sysmanage-agent
      when: ansible_os_family == "RedHat"

    # openSUSE Tumbleweed and SLES 15: the signed SysManage RPM repositories
    - name: Import the SysManage RPM signing key
      ansible.builtin.rpm_key:
        key: https://repo.sysmanage.org/agent/rpm/RPM-GPG-KEY-sysmanage
      when: ansible_os_family == "Suse"

    - name: Add the SysManage RPM repository
      community.general.zypper_repository:
        name: sysmanage-agent
        repo: "https://repo.sysmanage.org/agent/rpm/{{ 'sles/15' if ansible_distribution == 'SLES' else 'opensuse-tumbleweed' }}/x86_64"
      when: ansible_os_family == "Suse"

    - name: Install the agent (openSUSE)
      community.general.zypper:
        name: sysmanage-agent
      when: ansible_os_family == "Suse"

    - name: Write the agent configuration
      ansible.builtin.template:
        src: sysmanage-agent.yaml.j2
        dest: /etc/sysmanage-agent.yaml
        owner: sysmanage-agent
        group: sysmanage-agent
        mode: "0640"
      notify: Restart the agent

  handlers:
    - name: Restart the agent
      ansible.builtin.service:
        name: sysmanage-agent
        state: restarted
        enabled: true

Configuration Template

templates/sysmanage-agent.yaml.j2. The agent fills in its defaults for every setting the file leaves out; see the Agent Configuration Guide for the rest.

server:
  url: "{{ sysmanage_url }}"
  verify_ssl: true

{% if sysmanage_registration_key %}
security:
  registration_key: "{{ sysmanage_registration_key }}"
{% endif %}

For macOS, Windows and the BSDs, run the commands from Agent Installation through your tool: brew install bceverly/tap/sysmanage-agent on macOS and winget install --id sysmanage.sysmanage-agent --exact on Windows. The Alpine and BSD packages are direct downloads; check each one's .sha256 as the installation page shows.

Approving the Hosts

Every new host registers and waits on the Hosts page until it is approved. For a large rollout you can select many pending hosts there and approve them together.

To approve hosts as they arrive, create a registration key with auto-approval under Settings → Access Groups and deliver it as security.registration_key, as the template above does. A key can also place hosts in an access group. Registration keys need a Professional+ Enterprise license. Treat an auto-approving key like a password and delete it when the rollout is done. See Agent Approval.

On a multi-tenant server, also deliver the tenant's enrollment token as security.enrollment_token; it decides which tenant the host joins.

Mass Deployment Strategies

Phased Rollout

  • Deploy to test environment first
  • Gradual rollout by groups
  • Monitor each phase before proceeding
  • Rollback plan for issues

Canary Deployment

  • Deploy to small subset first
  • Monitor metrics and performance
  • Gradually increase deployment size

A large fleet reconnecting at once is a load the server is built for, within limits; the Scaling Guide has the measurements.

Deployment Checklist

Pre-deployment

  • Server connectivity verified
  • Outbound port 443 from every host to the server allowed
  • Server certificate trusted by the hosts (a public CA, or your own CA installed on them)
  • Agent configuration templates ready
  • Backup and rollback plan documented

During Deployment

  • Monitor deployment progress
  • Verify agent connectivity
  • Check service status on each host
  • Approve the new hosts, or confirm the registration key approved them
  • Test basic agent functionality

Post-deployment

  • Confirm all agents are reporting
  • Verify metric collection
  • Delete any auto-approving registration key you no longer need
  • Document deployment configuration

Deployment Troubleshooting

Agent Not Connecting

  • Check network connectivity to server
  • Check server.url against the name on the server's certificate
  • Check certificate validity
  • Review firewall rules
  • Examine agent logs

Package Installation Fails

  • Check that the host can reach the repository
  • Check that the signing key was imported before the repository was added
  • Check that the release is one the repository builds for

Service Startup Failures

  • Check system service logs
  • Verify configuration file syntax
  • Ensure proper file permissions
  • Check available system resources
