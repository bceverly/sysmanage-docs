Agent Installation Guide

Install the SysManage agent from the package for your platform, point it at your server, and approve the host. Building from source is only needed for development.

Before You Begin

  • A running SysManage server that this host can reach on port 443, by the name on its TLS certificate.
  • An enrollment token, if the server uses multi-tenancy. It decides which tenant the host joins; create one in the server's web interface.
  • Root, sudo or administrator access on the host, to install the package.

You do not need to install Python or any build tools yourself: each package brings what the agent needs. The agent opens no listening port; it connects out to the server.

Install from Packages (Recommended)

Ubuntu (Launchpad PPA)

The agent is published in the ppa:bceverly/sysmanage-agent Launchpad PPA for Ubuntu 22.04 LTS, 24.04 LTS and 26.04 LTS. This is the recommended way to install it on Ubuntu.

Packages are built for amd64, arm64 and riscv64 on every listed release.

sudo add-apt-repository ppa:bceverly/sysmanage-agent
sudo apt update
sudo apt install sysmanage-agent

The package creates the sysmanage-agent service account and its sudo rules, writes /etc/sysmanage-agent.yaml from the example, and starts the service. Until you set your server's address in that file, the agent keeps trying the placeholder address, so finish After Installing next. Later releases arrive through sudo apt upgrade.

Other Platforms

Every other platform installs from a package repository or a signed download on repo.sysmanage.org, the SysManage package mirror. The same files are attached to each GitHub release. Where a command uses VERSION, it reads the latest release number from the mirror first.

Debian 12 and newer (amd64 and arm64) install from the SysManage APT repository. Ubuntu can use it too, but the PPA above is the recommended source on Ubuntu.

# Install the archive signing key
sudo install -d -m 0755 /usr/share/keyrings
curl -fsSL https://repo.sysmanage.org/agent/sysmanage-archive-keyring.gpg \
  | sudo tee /usr/share/keyrings/sysmanage-archive-keyring.gpg > /dev/null

# Add the repository, verified against that key
echo "deb [signed-by=/usr/share/keyrings/sysmanage-archive-keyring.gpg] https://repo.sysmanage.org/agent/deb stable main" \
  | sudo tee /etc/apt/sources.list.d/sysmanage-agent.list

sudo apt update
sudo apt install sysmanage-agent

RHEL, Rocky Linux, AlmaLinux and Oracle Linux 8, 9 and 10, CentOS Stream 9 and 10, Fedora 43 and Amazon Linux 2023 install from the bceverly/sysmanage-agent Fedora Copr project:

sudo dnf install epel-release      # RHEL-family only; skip on Fedora and Amazon Linux
sudo dnf copr enable bceverly/sysmanage-agent
sudo dnf install sysmanage-agent

For EL9 hosts that cannot reach Copr, the same signed packages (x86_64 and aarch64) are in a DNF repository on the mirror:

sudo tee /etc/yum.repos.d/sysmanage-agent.repo <<'EOF'
[sysmanage-agent]
name=SysManage Agent
baseurl=https://repo.sysmanage.org/agent/rpm/el9/$basearch
enabled=1
gpgcheck=1
gpgkey=https://repo.sysmanage.org/agent/rpm/RPM-GPG-KEY-sysmanage
EOF
sudo dnf install sysmanage-agent

openSUSE Leap 15, openSUSE Tumbleweed and SUSE Linux Enterprise Server 15 (x86_64) install from the signed RPM repositories on the mirror. Add the one for your distribution:

sudo rpm --import https://repo.sysmanage.org/agent/rpm/RPM-GPG-KEY-sysmanage

# openSUSE Leap 15
sudo zypper addrepo https://repo.sysmanage.org/agent/rpm/opensuse-leap/15/x86_64 sysmanage-agent

# openSUSE Tumbleweed
sudo zypper addrepo https://repo.sysmanage.org/agent/rpm/opensuse-tumbleweed/x86_64 sysmanage-agent

# SUSE Linux Enterprise Server 15
sudo zypper addrepo https://repo.sysmanage.org/agent/rpm/sles/15/x86_64 sysmanage-agent

sudo zypper refresh
sudo zypper install sysmanage-agent

Arch Linux installs the sysmanage-agent package from the AUR, with any AUR helper:

yay -S sysmanage-agent

Alpine Linux 3.20, 3.21 and 3.22 install a package from the mirror. Set ALPINE to your release (alpine320, alpine321 or alpine322), check the download, and install it as root:

ALPINE=alpine322
VERSION=$(wget -qO- https://repo.sysmanage.org/agent/alpine/latest.txt)
BASE=https://repo.sysmanage.org/agent/alpine/packages/$VERSION
wget "$BASE/sysmanage-agent-$VERSION-$ALPINE.apk" "$BASE/sysmanage-agent-$VERSION-$ALPINE.apk.sha256"
sha256sum -c "sysmanage-agent-$VERSION-$ALPINE.apk.sha256"
apk add --allow-untrusted "./sysmanage-agent-$VERSION-$ALPINE.apk"
rc-update add sysmanage-agent default

macOS installs the package from the mirror. It installs the agent in /usr/local/lib/sysmanage-agent and registers the com.sysmanage.agent launch daemon.

VERSION=$(curl -fsSL https://repo.sysmanage.org/agent/mac/latest.txt)
curl -fLO "https://repo.sysmanage.org/agent/mac/packages/$VERSION/sysmanage-agent-$VERSION-macos.pkg"
sudo installer -pkg "sysmanage-agent-$VERSION-macos.pkg" -target /

Homebrew users can install it from the SysManage tap instead: brew install bceverly/tap/sysmanage-agent.

Download the installer for your architecture from the latest release and run it as an administrator. Use the .exe bundle (sysmanage-agent-X.Y.Z-windows-x64.exe, or -windows-arm64.exe on ARM): it installs the Visual C++ runtime and Python first, then the agent, and registers the SysManageAgent service.

The plain .msi is for hosts that already have Python, and for unattended deployment with msiexec /i sysmanage-agent-X.Y.Z-windows-x64.msi /qn. The agent is also published to winget as sysmanage.sysmanage-agent, though winget can trail the latest release.

FreeBSD 14 installs the package from the mirror:

VERSION=$(fetch -qo - https://repo.sysmanage.org/agent/freebsd/latest.txt)
sudo pkg add "https://repo.sysmanage.org/agent/freebsd/packages/$VERSION/sysmanage-agent-$VERSION.pkg"
sudo sysrc sysmanage_agent_enable=YES

A pre-built package is published for OpenBSD 7.9 and 8.0; it needs no compiler. Use openbsd79 or openbsd80 to match your release. The package is not signed by the OpenBSD project, so check its checksum and install it with -D unsigned:

VERSION=$(ftp -o - https://repo.sysmanage.org/agent/openbsd/latest.txt)
BASE=https://repo.sysmanage.org/agent/openbsd/packages/$VERSION
ftp "$BASE/sysmanage-agent-$VERSION-openbsd80.tgz" "$BASE/sysmanage-agent-$VERSION-openbsd80.tgz.sha256"
sha256 -c "sysmanage-agent-$VERSION-openbsd80.tgz.sha256"
doas pkg_add -D unsigned "./sysmanage-agent-$VERSION-openbsd80.tgz"
doas rcctl enable sysmanage_agent

NetBSD installs the package from the mirror, as root:

VERSION=$(ftp -o - https://repo.sysmanage.org/agent/netbsd/latest.txt)
BASE=https://repo.sysmanage.org/agent/netbsd/packages/$VERSION
ftp "$BASE/sysmanage-agent-$VERSION.tgz" "$BASE/sysmanage-agent-$VERSION.tgz.sha256"
sha256 -c "sysmanage-agent-$VERSION.tgz.sha256" "sysmanage-agent-$VERSION.tgz"
pkg_add "./sysmanage-agent-$VERSION.tgz"
echo 'sysmanage_agent=YES' >> /etc/rc.conf

Sandboxed Packages (Limited)

A strictly confined Snap (sudo snap install sysmanage-agent-strict --edge, edge channel only) and a Flatpak bundle (attached to each GitHub release) also exist. Their sandboxes stop them from managing packages, services or users, so they can only report on the host. Use a regular package above unless you need a read-only agent.

After Installing

Step 1: Point the Agent at Your Server

Edit the configuration file: /etc/sysmanage-agent.yaml on Linux, macOS and the BSDs, or C:\ProgramData\SysManage\sysmanage-agent.yaml on Windows. Set server.url to your server. If the server uses multi-tenancy, add the enrollment token under the top-level security section, as below; a token anywhere else in the file is ignored, and the host registers without a tenant.

server:
  url: "https://sysmanage.example.com"
  verify_ssl: true

security:
  enrollment_token: "paste-the-token-here"

Step 2: Start or Restart the Agent

The agent reads its configuration only when it starts, so restart it after every change:

sudo systemctl restart sysmanage-agent                     # Linux (systemd)
sudo rc-service sysmanage-agent restart                    # Alpine Linux
sudo launchctl kickstart -k system/com.sysmanage.agent     # macOS
Restart-Service SysManageAgent                              # Windows (administrator PowerShell)
sudo service sysmanage_agent restart                       # FreeBSD, NetBSD
doas rcctl restart sysmanage_agent                         # OpenBSD

Step 3: Approve the Host

Within a minute the host appears on the server's Hosts page as waiting for approval. Approve it there, and the agent starts reporting inventory, updates and health. If it does not appear, check the agent's log: /var/log/sysmanage-agent/agent.log, or C:\ProgramData\SysManage\logs\agent.log on Windows.

How the Agent Gets Its Privileges

On Linux, the packages run the agent as the unprivileged sysmanage-agent user. It runs privileged commands, such as installing updates or restarting a service, through a sudo allowlist that names exactly those commands, so it never holds root itself. See Privileged Execution for what is allowed and how to adjust it.

Upgrading

Upgrade with the same package manager you installed with, for example sudo apt upgrade or sudo dnf upgrade. Your configuration file is kept. On platforms installed from a downloaded file, download the new release and install it the same way.

Building from Source (Development)

Build from source to work on the agent itself. You need Python 3.9 or newer with its development headers, a C compiler, and make (gmake on the BSDs).

git clone https://github.com/bceverly/sysmanage-agent.git
cd sysmanage-agent
make install-dev
cp installer/ubuntu/sysmanage-agent.yaml.example sysmanage-agent.yaml   # then set server.url
make start

A source checkout reads sysmanage-agent.yaml in the project directory when /etc/sysmanage-agent.yaml does not exist. For problems after installation, see Troubleshooting.
