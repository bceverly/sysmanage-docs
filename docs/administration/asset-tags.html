Asset Tags

An asset tag is your organization's inventory number for a piece of hardware -- usually printed on a label stuck to it. In SysManage the tag belongs to the machine, not to the operating system running on it. A laptop that boots Windows, Ubuntu and OpenBSD appears as three hosts but carries one tag, and reinstalling the OS keeps the tag.

Hosts and machines

Every agent reports the hardware identity of the machine it runs on: the SMBIOS system UUID, plus the system and baseboard serial numbers as corroboration. Hosts that report the same identity are linked to one machine automatically. Different operating systems print the UUID in different byte orders; SysManage treats both orders as the same machine, so a multi-boot machine is never split in two.

For now, give each operating system on a multi-boot machine its own hostname (for example t480-ubuntu). An operating system that reports the same hostname as another host is refused when it registers, even on the same machine; supporting one hostname across every operating system is planned.

Where the identity comes from on each platform:

  • Linux /sys/class/dmi/id -- readable only by root, so the agent needs privileged mode.
  • Windows Win32_ComputerSystemProduct.
  • FreeBSD kenv smbios.system.uuid.
  • OpenBSD sysctl hw.uuid and hw.serialno.
  • NetBSD machdep.dmi.system-uuid -- readable only by root.
  • macOS the platform UUID from ioreg.

When an identity cannot be read, the Machine card says why -- the agent is not running in privileged mode, the read failed, or the firmware ships a vendor placeholder UUID that identifies nothing. A host with no usable identity is never guessed onto a machine.

The hardware identity groups hosts; it never authenticates one. Any local user can read it, and a virtual machine can be given any UUID, so it plays no part in how an agent proves who it is.

Clones and conflicts

Some matches are held for an administrator instead of being linked:

  • Virtual clone A virtual machine reporting the identity of a machine another host is already on is usually a clone that kept its UUID.
  • Serial mismatch The same UUID with a different system serial number -- two machines whose vendor reused a UUID.

The host's Machine card shows the conflict with Same machine and Different machine buttons. The decision is recorded in the audit log, and a machine you mark as different keeps its own record on later reports. A container that reads its parent's hardware is not treated as another operating system on the machine.

The naming scheme

Under Settings > Asset Tags you define what a valid tag looks like with a builder: a prefix, a separator, a number of digits (zero padded) and an optional suffix. The live preview shows a sample tag, tags that pass and fail, and the next free number. An advanced mode accepts a regular expression for schemes the builder cannot express.

With Enforce at entry on, a tag that does not fit is refused when it is entered; with it off, the tag is accepted and reported. Changing the scheme never rewrites existing tags -- it lists the ones that no longer conform so you can change them yourself. Tags are unique ignoring case, so NST-00042 and nst-00042 are the same tag.

Assigning and finding tags

Set, change or clear a tag from the Machine card of any host on the machine; the tag is checked against the scheme as you type. The Hosts grid has an Asset Tag column, a search on it, and an Untagged only switch, and the command palette finds a host by its tag. Every change is recorded in the audit log.

Importing and exporting tags

A CSV file with an asset_tag column and a system_uuid or system_serial column assigns tags in bulk. Choosing the file shows what every row would do before anything is written:

  • Will assign The machine gets the tag (replacing any tag it had).
  • Unchanged The machine already has it.
  • Will wait for the machine No machine has reported this identity yet; the tag becomes a pending tag.
  • Fails the scheme The tag does not fit the naming scheme.
  • Duplicate Another machine or pending tag already has the tag, or the file repeats a tag or a machine.
  • Ambiguous More than one machine reports the UUID; add the serial number to choose one.
  • Invalid The row names no usable identifier -- a malformed UUID or a vendor placeholder such as To Be Filled By O.E.M.
  • Skipped The tag cell is blank. An import never clears a tag.

Applying sends the file again and the server checks every row once more, so nothing changed since the preview can slip through. A file that swaps two machines' tags reports duplicates; clear one of the tags first. Export CSV writes every machine and pending tag in the same columns -- plus vendor, model and hosts -- so an exported file can be edited and imported back.

Pending tags

A tag imported for a machine that has not reported in yet is kept as a pending tag. It is applied automatically the first time a machine with that UUID or serial number reports in without a tag. It never replaces a tag the machine already has, and if another machine has taken the tag in the meantime it stays pending rather than creating a second owner.

This lets you tag hardware before it has an operating system. When a serial number in the file was seen by bare-metal discovery, the preview shows that box's MAC address, so a machine on the netboot parking lot can be tagged before it is installed.

Reports

The Registered Hosts report includes each host's asset tag, and the Untagged Machines report lists every machine with no tag yet -- with every operating system installed on it, its vendor, model, serial number and system UUID.

Permissions

Changing the scheme, setting tags, importing and removing pending tags need the Manage Asset Tags role; anyone signed in can see tags and export them. Resolving a clone or serial-mismatch conflict needs Approve Host Registration. On a server upgraded to this release, users who could already edit host tags receive Manage Asset Tags automatically.

Edition Requirements

Machines, asset tags, the naming scheme, CSV import and export, and pending tags are available in all editions of SysManage, including the Community Edition. The rendered reports (Registered Hosts with asset tags, and Untagged Machines) are part of the Professional+ reporting engine.
