Setting Up the Backup Storage Host

The storage host serves the NFS share every backed-up host writes to, and runs the jobs that seal, prune and check the backups. It must be a managed host with the SysManage agent and restate 2.0 or later. This page sets one up on FreeBSD with ZFS, the setup SysManage is tested with, and mounts it on Linux hosts.

1. The datasets and the backup user

Create a dataset for the share and one for the repositories, and an unprivileged user that will own everything the hosts write. Root on a backed-up host must never be root on the storage host.

zfs create -o mountpoint=/srv/backups zroot/sysmanage-backups
zfs create zroot/sysmanage-backups/restate
pw groupadd restate
pw useradd restate -g restate -d /nonexistent -s /usr/sbin/nologin -c "restate backup writer"
chown restate:restate /srv/backups/restate
chmod 0700 /srv/backups/restate

2. The NFSv4 export

In /etc/exports, make /srv/backups the NFSv4 root and export the repositories to your backed-up hosts, mapping every client user to restate:

V4: /srv/backups -sec=sys 192.0.2.10 192.0.2.11
/srv/backups/restate -alldirs -mapall=restate -sec=sys 192.0.2.10 192.0.2.11

List each backed-up host's address, or use -network for a subnet you trust.

3. The NFS services and locking

In /etc/rc.conf:

rpcbind_enable="YES"
nfs_server_enable="YES"
nfsv4_server_enable="YES"
mountd_enable="YES"

In /etc/sysctl.conf:

vfs.nfsd.enable_locallocks=1
vfs.nfsd.server_min_nfsvers=4
vfs.nfsd.enable_stringtouid=1
vfs.nfs.enable_uidtostring=1

vfs.nfsd.enable_locallocks=1 is required: it makes a lock taken by a job on the storage host and a lock taken by a host over NFS see each other, so a backup and a prune never run on one repository at the same time. Then start the services, or reboot:

service rpcbind start
service mountd start
service nfsd start

4. Mounting the share on each host

On each Linux host you back up, install the NFS client (nfs-common on Debian and Ubuntu), create the mount point and add a line to /etc/fstab. The share is the path below the NFSv4 root, so /srv/backups/restate is mounted as /restate:

nas.example.lan:/restate  /mnt/backups  nfs4  vers=4.2,proto=tcp,hard,_netdev,nofail,x-systemd.automount,x-systemd.mount-timeout=30  0  0

nofail and x-systemd.automount let the host boot when the storage host is down, and mount the share the first time a backup reaches for it. Files a host writes there belong to restate on the storage host.

5. The target in SysManage

On the Backups page, set up the target with this storage host, Path on the storage host /srv/backups/restate, Mount point on each host /mnt/backups, and Seal each backup as a ZFS snapshot of zroot/sysmanage-backups/restate. The target card then shows the storage host's filesystem as zfs. See Fleet Backups for the rest.

A FreeBSD storage host

FreeBSD has no systemd, so on a FreeBSD storage host the agent starts restate's prune and check jobs itself, under daemon(8), so they keep running if the agent restarts. restate is found in /usr/local/sbin. A FreeBSD host can only be a storage host; choosing one as a backed-up host is refused.

When the agent does not run as root, its sudoers file allows exactly restate run of a prune, check, copy or du job file in /etc/restate/jobs.d, through a regular expression rather than a wildcard, so no extra option can be added to the command. It needs sudo 1.9.10 or later.

Other storage

A Linux storage host works the same way with any NFSv4 server that maps clients to one unprivileged user. On btrfs, make the storage path a subvolume (btrfs subvolume create /srv/backups/restate) and choose the btrfs seal. On ext4 or XFS backups work but cannot be sealed, and the target card warns you.
