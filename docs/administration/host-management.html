Host Management

Organizing and managing hosts, agents, and inventory across your environment.

Overview

Host management in SysManage involves organizing, monitoring, and maintaining all registered hosts in your infrastructure. This includes agent deployment, host grouping, approval processes, and lifecycle management across diverse environments.

Key Concepts

  • Host Registration: Process by which new hosts join the SysManage system
  • Agent Lifecycle: Management of agent installation, updates, and decommissioning
  • Host Groups: Logical organization of hosts for management and monitoring
  • Tags and Metadata: Labeling system for categorizing and filtering hosts
  • Inventory Management: Tracking hardware, software, and configuration details

Host Registration and Approval

Registration Process

When a new agent is installed and configured, it follows this registration process:

  1. Initial Connection: Agent establishes secure connection to server
  2. Identity: The server issues the host a secret host token, which the agent presents on every later connection
  3. System Discovery: Agent reports hardware and software inventory
  4. Approval Queue: Host appears in admin interface for approval
  5. Administrator Review: Admin reviews host details and approves/rejects
  6. Active Management: The server begins processing the approved host's reports and sending it commands; it also issues the host a client certificate

Approval Workflow

Reviewing Pending Hosts

Pending hosts appear on the Hosts page with status pending; select them and choose Approve Selected. The page is:

Hosts

For each pending host, review:

  • Hostname and FQDN: Verify the host identity
  • IP Address: Confirm network location
  • Operating System: Check OS type and version
  • Hardware Specifications: Review CPU, memory, and disk
  • Agent Version: Ensure compatible agent version

Approval Criteria

Consider these factors when approving hosts:

  • Host is owned by your organization
  • Network location is appropriate
  • Operating system is supported
  • You expected this host to register
  • Host meets security requirements

Security Warning

Only approve hosts that you recognize and trust. An approved host can report data that you will act on. When in doubt, investigate further before approving.

Host Organization

Host Groups

SysManage has two kinds of host grouping:

  • Access groups (all editions): named, nestable scopes that hosts and users belong to, used to limit which hosts a user can see and manage. Create them under Settings → Access Groups; see Access Groups and Update Profiles.
  • Fleet groups (Enterprise): groups for bulk operations, with optional parent/child nesting and dynamic membership rules that match hosts by platform, platform release, approval status, tag, FQDN or membership of another group. See Fleet Engine.

Common ways to group hosts: by environment (production, staging), by function (web, database), by location, or by owning team. Tags, described next, work in every edition.

Tagging and Metadata

Use tags to add flexible metadata to hosts:

Common Tag Categories

  • Environment: env:production, env:staging
  • Application: app:wordpress, app:database
  • Owner: owner:engineering, owner:devops
  • Criticality: critical:high, critical:low
  • Maintenance: backup:daily, patch:weekend
  • Compliance scope: scope:cardholder, scope:regulated

Tag Management

Manage tags through multiple interfaces:

  • Individual Host: Edit tags on host detail page
  • Bulk Operations: Apply tags to multiple hosts at once
  • API Integration: Automate tagging via REST API

Agent Lifecycle Management

Agent Deployment

Deployment Methods

  • Packages: Install the agent from its native package (deb, rpm, MSI, pkg and others) on each host
  • Your own automation: Install the package and write the agent configuration with the tool you already use (for example an Ansible playbook)
  • From SysManage: Enterprise can install the agent on new hosts as part of provisioning

Deployment Best Practices

  • Test deployment in staging environment first
  • Use configuration management for consistency
  • Implement gradual rollout for large environments
  • Monitor deployment progress and success rates
  • Have rollback procedures ready
  • Document deployment procedures

Agent Updates

Update Strategy

Plan agent updates carefully to maintain stability:

  • Staged Rollout: Update small groups progressively
  • Testing Phase: Test updates on non-production hosts first
  • Monitoring: Watch for issues during and after updates
  • Rollback Plan: Be prepared to revert if problems occur
  • Communication: Notify stakeholders of planned updates

Update Process

  1. Review agent update release notes
  2. Test update in staging environment
  3. Schedule maintenance window
  4. Update agents in defined order
  5. Verify agent connectivity and functionality
  6. Monitor for any issues or anomalies
  7. Document update completion

Agent Troubleshooting

Common Issues

  • Connectivity Problems: Network, firewall, certificate issues
  • Performance Issues: High CPU/memory usage, slow responses
  • Data Collection Failures: Missing or incorrect data
  • Authentication Errors: Certificate or credential problems
  • Configuration Issues: Incorrect agent settings

Diagnostic Tools

  • Agent Logs: Review detailed agent activity logs
  • Connectivity Tests: Test network connectivity to server
  • Certificate Validation: Verify certificate validity and trust
  • Configuration Validation: Check agent configuration syntax
  • Performance Monitoring: Monitor agent resource usage

Infrastructure Inventory Management

Hardware Inventory

SysManage automatically collects and maintains hardware inventory:

Collected Information

  • System Information: Operating system, version, architecture, and system serial number where the platform reports it
  • CPU Details: Type, cores, threads, frequency
  • Memory: Total and available memory
  • Storage: Disks, partitions, file systems, capacity
  • Network: Interfaces, MAC addresses, IP addresses

Inventory Reports

The built-in reports that draw on inventory:

  • Registered Hosts: Every host with its platform and status
  • Hosts with Tags: Hosts listed by tag
  • Untagged Machines: Hosts that carry no tag
  • Firewall and Antivirus Status: Protection state per host
  • Asset tags: Record your own asset numbers and ownership; see Asset Tags

Software Inventory

Track installed software across all managed hosts:

Software Tracking

  • Operating System: Version, patch level, configuration
  • Installed Packages: All installed software packages
  • Running Services: Active services and processes
  • Security Updates: Available and missing security patches

Software Reports

  • Software Inventory: Installed packages per host
  • Updates: Available and security updates per host
  • Package Search: Search the packages available to your hosts' package managers

Bulk Operations

Mass Management Actions

Perform actions on multiple hosts simultaneously:

Available Bulk Operations

  • Approval: Approve several pending hosts at once
  • Tag Management: Apply or remove tags in bulk
  • Software Installation: Install packages on multiple hosts
  • Security Updates: Apply security patches across hosts

Bulk Operation Process

  1. Select hosts using filters or groups
  2. Choose the operation to perform
  3. Configure operation parameters
  4. Check the list of selected hosts
  5. Run it now, or let maintenance windows hold it until each host's window opens
  6. Monitor operation progress
  7. Review operation results

Caution

Bulk operations can affect many hosts simultaneously. Always test operations on a small subset first and have rollback procedures ready.

Automation Integration

  • REST API: everything in the web interface is available through the API, using a token or an API key; see the API documentation.
  • Configuration management: SysManage drives configuration tools on your hosts. Every edition can apply an Ansible playbook to a single host; Enterprise adds Puppet, Salt and Chef, saved profiles, assignment to hosts, schedules and fleet-wide runs. See Configuration Management.

Host Management Best Practices

Organizational Best Practices

  • Consistent Naming: Use standardized hostname conventions
  • Logical Grouping: Organize hosts by function, environment, and ownership
  • Comprehensive Tagging: Tag all hosts with relevant metadata
  • Documentation: Document host purposes and configurations
  • Access Controls: Limit host access based on roles and responsibilities

Operational Best Practices

  • Regular Audits: Periodically review host inventory and status
  • Lifecycle Management: Plan for host provisioning and decommissioning
  • Change Management: Document and track all host changes
  • Performance Monitoring: Monitor host performance and capacity
  • Security Compliance: Ensure hosts meet security requirements

Security Best Practices

  • Server Certificate: Keep the server's TLS certificate valid so agents can verify it
  • Network Security: Use secure communication channels
  • Access Logging: Log all host access and administrative actions
  • Vulnerability Management: Track and remediate security vulnerabilities
  • Incident Response: Have procedures for handling compromised hosts

Host List Controls

The Hosts page provides several controls above and below the host list for filtering, searching, and acting on the displayed hosts. The following controls are available:

  • Search box and column selector: Enter a search term to filter the list. The accompanying column selector chooses which field the term is matched against: FQDN, Platform, IPv4, or IPv6. Matching is case-insensitive and matches any host whose chosen field contains the term.
  • Filter by Tags: A multi-select control that limits the list to hosts carrying the selected tags. Selecting multiple tags uses AND logic, so a host must have all selected tags to appear.
  • Child host filter (All / Parents / Children): A toggle that limits the list to all hosts, parent (virtualization) hosts only, or child hosts only. This is a Professional+ feature and is hidden on community builds without the container engine module.
  • Column Visibility: Opens a menu to show or hide individual columns in the host list, with an option to reset back to the defaults. Your selections are remembered for this grid.
  • Refresh All Data: Requests a full inventory data refresh from each selected host. Enabled only when one or more hosts are selected.
  • Broadcast Refresh: Sends a refresh-inventory broadcast to every connected agent at once. A confirmation prompt is shown first, and the result reports how many hosts were reached.
  • Get Diagnostics: Requests diagnostic data collection from a single host. Enabled only when exactly one host is selected; results appear on that host's detail page when available.
