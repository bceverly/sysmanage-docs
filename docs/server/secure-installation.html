SysManage Secure Installation

The setup script for source checkouts: it gives a fresh development or test server its own secrets, a new database schema, OpenBAO and a first administrator.

Installed from a package? You do not need this script. The packages generate the secrets and initialize OpenBAO themselves; follow After Installing instead. This script is for source checkouts, and it rebuilds the database.

When to Use It

Production servers run from the native packages, which set everything up on install. A source checkout, made for development as Building from Source describes, starts with nothing: no secrets, no schema and no user. sysmanage_secure_installation fills that gap in one run. It is inspired by MySQL's mysql_secure_installation.

It deletes data. The script drops every table in the configured database and rebuilds the schema, so run it only on a checkout whose data you do not need. It asks you to type yes before it starts.

What the Script Accomplishes

In order, the script:

  1. Asks for the database connection, the first administrator's email address, password and name, and the deployment mode (single-tenant, or the multi-tenant control plane)
  2. Checks that it can reach the database, and installs the development dependencies (make install-dev)
  3. Generates a new JWT secret and password salt and writes them to the configuration file
  4. Stops a running server, drops all tables, and runs the database migrations to rebuild the schema
  5. Starts and initializes a local OpenBAO if it is installed, unseals it, enables the key-value secrets engine, and saves its credentials to .vault_credentials in the project directory
  6. Offers to install the local telemetry stack (OpenTelemetry Collector and Prometheus)
  7. Creates the administrator, with an Argon2 password hash, and stores the generated secrets in OpenBAO when it is reachable

It edits the first configuration file it finds, in this order: /etc/sysmanage.yaml (C:\ProgramData\SysManage\sysmanage.yaml on Windows), then sysmanage.yaml and sysmanage-dev.yaml in the current directory, then ~/sysmanage.yaml. Run it from the project root of the checkout.

Usage Guide

Prerequisites

  • SysManage installation with virtual environment set up (make install-dev)
  • Administrative/root privileges on the system
  • PostgreSQL database running and accessible
  • OpenBAO binary available (automatically installed with make install-dev)

Running the Script

The script is interactive and takes no options. The wrapper finds the checkout's virtual environment and asks for elevation (sudo, doas, or Administrator on Windows) if it needs it.

# From the root of the source checkout
cd /path/to/sysmanage
./scripts/sysmanage_secure_installation

# Then start the development server
make start

On Windows, run scripts\sysmanage_secure_installation.cmd or scripts\sysmanage_secure_installation.ps1 from an administrator terminal.

Troubleshooting

Privilege Issues

Problem: Script fails with permission denied errors

Solution:

  • Ensure you have administrative privileges on your system
  • On Linux/macOS: Use sudo or ensure your user is in sudoers
  • On FreeBSD/OpenBSD: Configure doas or use sudo
  • On Windows: Run terminal as Administrator

Virtual Environment Issues

Problem: "Virtual environment not found" error

Solution:

# Create and set up virtual environment
make install-dev

# Verify virtual environment exists
ls -la .venv/

Database Connection Issues

Problem: Database connection failures during migration

Solution:

  • Verify PostgreSQL is running: systemctl status postgresql
  • Check database credentials in configuration file
  • Ensure database user has CREATE privileges
  • Test connection manually: psql -h host -U user -d database

OpenBAO Installation Issues

Problem: OpenBAO binary not found or initialization fails

Solution:

  • Install OpenBAO: make install-dev (includes OpenBAO)
  • Manually install OpenBAO from official releases
  • Check firewall settings for localhost connections
  • Without OpenBAO the script skips that step and keeps the secrets in the configuration file, which is acceptable for development only

Post-Installation Steps

Post-Installation Checklist

  • Secure Credentials: Store the generated .vault_credentials file in a secure location
  • Start Services: Use make start to launch all services
  • Access Web Interface: open the development web interface at http://localhost:3000
  • Login: Use the admin credentials you created during installation
  • Deploy Agents: Install and approve SysManage agents on your infrastructure
