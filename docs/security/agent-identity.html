Agent Identity

How the server knows that an agent is the host it claims to be, and why a hostname is never enough.

A Host Is Its Credential, Not Its Name

Hostnames are public: they are in DNS, in certificates and in inventories. So every agent holds a host token, a secret the server issues once, when the host is first registered, and the agent keeps in its own database. The server identifies an agent by that token, never by its hostname or its address.

How an Agent Gets Its Token

  • A new host gets its id and token from the registration that created it, and from no other.
  • Registering a name that already exists returns no credential: knowing a host's name is not proof of being that host.
  • A lost reply (a timeout, a server restart at the wrong moment) does not lock the agent out. The agent sends the same random value with every registration attempt, and the server recognizes the retry and sends the credential again. That value stops working the first time the agent proves its token.
  • The agent keeps its token across restarts and upgrades; a reply that does not carry one never erases it.

Every Connection Is Verified

When an agent connects, it presents its host id and its token. A connection that claims an existing host without the right token is refused: nothing is bound to it, it receives no token, and the server logs the attempt and writes an audit entry with the claimed host and the source address.

After that, every message on a connection may only touch that connection's own host, and a host's commands go only to its verified connection.

Older Agents

Agents released before this protection identify with their host id alone. They are still accepted, so upgrading the server does not lock out a fleet. Once an upgraded agent proves its token, its host is marked as requiring one, and the host id alone is refused for that host from then on.

Reinstalled Hosts

A reinstalled host has lost its token, so it can no longer connect as itself. An administrator re-enrolls it from the host page, which clears the old credential and returns the host to pending approval; see Agent Approval.

How This Is Tested

Every change to the server runs an impersonation check: a real server, a legitimate agent, and an attacker that knows only that agent's hostname. The attacker tries to register the name again, to connect as the host, to send data with no token or a wrong one, and to receive the host's commands. Every attempt must fail, while the legitimate agent's own updates and an older agent's connection must succeed.
