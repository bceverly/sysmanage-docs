Secrets Management with OpenBAO

Store certificates, SSH keys, and credentials in OpenBAO and deploy them to managed hosts.

Professional+ Required

Secrets management requires a Professional or Enterprise license, which loads the secrets_engine module. Without it, the secrets endpoints return a license-required error.

How SysManage Uses OpenBAO

SysManage integrates with OpenBAO to store and deliver secrets for your infrastructure -- certificates, SSH keys, and credentials. The secret content is written to OpenBAO's KV store; the SysManage database keeps only the metadata (name, type, owner) and the OpenBAO path.

The Server's Own Secrets

Separately from the licensed secrets feature, the server in every edition can read its own sensitive settings (such as the recovery administrator password, the license key, and the MaxMind license key) from OpenBAO, falling back to sysmanage.yaml when OpenBAO is disabled or unreachable.

What is OpenBAO?

OpenBAO is an open-source secrets-management platform forked from the HashiCorp Vault codebase, with open governance under the Linux Foundation.

What OpenBAO Provides

Encryption at Rest

OpenBAO encrypts everything it stores; SysManage talks to it over its HTTP API using a token.

Dynamic Secrets

SysManage can issue short-lived credentials (leases) stored in OpenBAO with a time-to-live from 60 seconds to 24 hours (30 minutes by default), and renew or revoke them.

Features in SysManage

Automated Certificate Deployment

Deploy SSL/TLS certificates to managed hosts. OpenBAO stores the certificates and private keys; SysManage sends them to the agent on each target host, which writes them into the operating system's certificate directory.

  • Certificate storage in OpenBAO
  • Deployment to one or more hosts
  • Deployment status reported back by the agent
  • Secret operations recorded in the audit log

SSH Key Management

Store SSH keys centrally and deploy them to a chosen user on managed hosts.

  • Centralized SSH key storage and management
  • Deployment of key files into a user's ~/.ssh directory
  • Public, private, and CA key entries
  • Rotation schedules that track when each secret is next due for rotation

Credentials Vault

Store API keys, database credentials, and other sensitive values.

  • Content stored in OpenBAO, not in the SysManage database
  • Access controlled by SysManage security roles
  • Version history for each secret

Security Architecture

How a secret moves from upload to a managed host.

Data Flow

1

Storage

Secret content is stored in OpenBAO; metadata is stored in the SysManage database

→
2

Authentication

SysManage authenticates to OpenBAO with a token

→
3

Retrieval

Secrets are read from OpenBAO only when they are viewed or deployed

→
4

Encrypted Deployment

Secrets are sent to agents over the TLS-protected WebSocket connection

Security Principles

  • Authenticated access: Every secrets API call requires a logged-in user with the matching security role
  • Encryption at rest and in transit: OpenBAO encrypts stored data, and agent connections use TLS
  • Minimal exposure: Secret content is fetched from OpenBAO only when needed
  • Auditing: Secret operations are written to the audit log

Deployment Workflow

Certificate Deployment Process

1

Upload & Store

Upload certificates through the SysManage web interface; they are stored in OpenBAO

2

Select Targets

Choose the target hosts in the web interface

3

Secure Transfer

Certificates are sent to the agents over their TLS-protected WebSocket connections

4

Deployment & Verification

Agents write the certificates and report the result back to the server

SSH Key Deployment Process

1

Key Management

Store SSH keys in OpenBAO, with metadata in the SysManage database

2

User Assignment

Choose the target host and the user account to receive the keys

3

Automated Deployment

The agent writes the key files into that user's ~/.ssh directory

4

Access Verification

Review the deployment result and the audit log entries

Getting Started

To start using secrets management:

1. Set Up OpenBAO

The sysmanage_secure_installation script initializes and unseals OpenBAO if it is installed, and writes the connection settings into the server configuration.

2. Upload Secrets

Use the web interface to upload certificates, SSH keys, and other sensitive data.

3. Deploy

Select target hosts and deploy, then check the result and the audit log.
