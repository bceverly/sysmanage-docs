Network Security

What listens where, which connections SysManage makes, and how to firewall the server and agents.

Topology

Everything SysManage exposes is on one port: 443 on the server, served by nginx. The web interface is at /, the REST API under /api/, and the agent WebSocket under /ws and /api/agent/connect. Port 80 only redirects to 443. Agents always connect outbound to the server; the server never opens a connection to an agent.

Firewall Configuration

On the Server

  • Allow inbound TCP 443 (and 80, if you want the redirect) from the networks your administrators and agents are on. Block everything else inbound.
  • If PostgreSQL runs on another machine, allow TCP 5432 from the SysManage server to that machine only.
  • Allow outbound connections the features you use need: the license server (license.sysmanage.io, once a day by default, on Professional and Enterprise), vulnerability and advisory feeds from the operating-system vendors and NVD, GeoIP lookups, and your SMTP server. An installation with no outbound access can run as an air-gapped deployment.
# Example: ufw on an Ubuntu server
sudo ufw default deny incoming
sudo ufw allow 443/tcp
sudo ufw allow 80/tcp
sudo ufw enable

# Example: firewalld on a RHEL-family server
sudo firewall-cmd --permanent --add-service=https
sudo firewall-cmd --permanent --add-service=http
sudo firewall-cmd --reload

On Managed Hosts

  • Allow outbound TCP 443 to the SysManage server, plus whatever the host needs for its own package repositories.
  • No inbound rule is needed for SysManage.
  • If hosts reach the server through an HTTP proxy, set server.proxy in the agent configuration, or the standard HTTPS_PROXY and NO_PROXY environment variables.

Throttling and Proxies

  • Sign-in throttling: the server limits failed sign-in attempts per user and per client address and locks an account after repeated failures (5 by default, for 15 minutes).
  • API rate limiting: an in-process limiter that returns HTTP 429 is built in but off by default, because per-address limits can throttle every user behind one shared proxy address. Enable it with api.rate_limit.enabled and tune it for your deployment. WebSocket and agent traffic are never limited.
  • Trusted proxies: if a load balancer or reverse proxy sits in front of nginx, list its addresses in security.trusted_proxies. The server then takes the client address from X-Forwarded-For for logging and throttling; it ignores that header from anyone else.

SSL/TLS Hardening

The nginx configuration the installers ship accepts TLS 1.2 and 1.3 only, offers only AEAD cipher suites with forward secrecy (AES-GCM and ChaCha20-Poly1305), and sends HSTS and other security headers. Agents refuse anything older than TLS 1.2. See Agent Certificates and TLS.

Network Security Troubleshooting

# From a managed host: can the agent reach the server, and does TLS validate?
curl -sS -o /dev/null -w "%{http_code}\n" https://sysmanage.company.com/api/health

# On the server: is anything other than nginx listening on a public address?
sudo ss -tlnp
