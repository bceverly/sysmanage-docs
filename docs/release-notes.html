Release Notes

What each release added, newest first. Patch releases (the fourth number, as in 3.12.1.7) carry fixes for the release they belong to. Before upgrading, read Upgrading and Rolling Back. What comes next is on the roadmap.

3.12 -- Fleet backup and recovery (current)

Scheduled, deduplicated backups of each host to a storage host you run (restate, over NFSv4, append-only), with quiesce hooks for databases, a Backups page and file restore (Community); encrypted and signed backups with keys held in OpenBAO, key rotation and break-glass export, retention policies, scheduled verification, a drift timeline and package restore (Professional); iCloud Photos copied to local storage. Backups are in preview: usable now while the final production proof is completed. The 3.12.1.7 patch release fixes first-run problems found on fresh installs: nginx on Ubuntu 24.04, Debian 12 and RHEL 9, a first-administrator form that needs no email, the FreeBSD agent package, and installing packages from the console.

3.11 -- Hardware, time and asset visibility

Drive health (SMART and NVMe), degraded RAID arrays and ZFS pools, temperatures and hardware errors on every operating system, with email alerts; every host's clock measured against the server, resynchronized in one click and held to the bounds you set; asset tags bound to the physical machine, with a naming scheme, search, reports and CSV import.

3.10 -- Scale hardening

Built to stay steady when thousands of agents reconnect at once: spread-out agent schedules that send only what changed, faster and fairer message intake, one leader among server workers for background work, fleet-wide pushes in waves. Measured at 10,000 and 20,000 simulated agents -- see Performance and Scale.

3.9 -- Endpoint facts and the advisor

A queryable store of endpoint facts using the osquery schema on every operating system, an advisor with recommendations, malware detection with ClamAV and YARA, a threat-model questionnaire with a posture checklist, and discovery of devices on the network that have no agent.

3.8 -- Configuration management and drift

Desired-state configuration with Ansible and PowerShell DSC on single hosts (Community), and Puppet, Salt and Chef profiles, scheduled runs, fleet configuration jobs and drift detection with remediation to a baseline (Enterprise).

3.5 and 3.6 -- Provisioning

New machines from templates on libvirt and Proxmox, PXE boot and install media for bare metal, discovery of new machines, and first-boot enrollment; agents report what they can do so the server only offers actions a host supports.

3.3 and 3.4 -- Content lifecycle and image-mode hosts

Content views and lifecycle environments with gated promotion of repository snapshots, a Snap store proxy and offline Snap content, container image content, and management of image-mode (bootc and OSTree) hosts.

3.1 and 3.2 -- Patch and maintenance lifecycle

Vendor advisory management, maintenance windows with blackouts and emergency overrides, operating system end-of-life tracking and release upgrades, FIPS mode, and running against a high-availability PostgreSQL cluster.

3.0 -- Multi-tenancy and the versioned API

Many isolated fleets on one installation, each tenant in its own database with its own credentials (Enterprise SaaS), and the versioned REST API with API keys.

2.2 to 2.4 -- Virtualization, air-gap and federation

Virtual machine lifecycle (KVM, bhyve, vmm), observability integration, multi-factor sign-in, air-gapped installations with content brought in on media, and multi-site federation with a coordinator and site servers.

2.0 -- Foundation

Access groups, update profiles, compliance checks and generic deployment plans on the agent.

1.x -- The platform and the first commercial editions

The cross-platform agent and console for Windows, Linux, macOS, FreeBSD, OpenBSD and NetBSD, then the Professional and Enterprise editions: reporting, audit, secrets, containers, antivirus and firewall orchestration, automation and fleet operations.
