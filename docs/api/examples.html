API Examples

Copy-and-run recipes for the jobs people script most, each in Bash (curl and jq), Python (requests) and PowerShell (Invoke-RestMethod). Replace https://sysmanage.example.com with your server and HOST-ID with a host's ID. The REST API and API keys are part of every edition, Community included.

Authentication

With an API key (recommended for automation)

  1. Sign in to the web interface, open the user menu at the top right, and choose API Keys.
  2. Choose Create API Key, give it a Name that says what will use it, and optionally an Expires (optional) date. Choose Create.
  3. The API key created dialog shows the key, which starts with smk_. Copy it now: only its hash is stored, and it is never shown again.

Send it as a Bearer token. The key acts as you, with your roles, so a recipe that changes something needs a user with the role named in that recipe. Revoke a key from the same page; automation using it stops at once. The recovery account from sysmanage.yaml cannot create keys -- create a user first.

export SYSMANAGE_URL=https://sysmanage.example.com
export SYSMANAGE_API_KEY=smk_...        # the key you copied
curl -s -H "Authorization: Bearer $SYSMANAGE_API_KEY" "$SYSMANAGE_URL/api/v1/hosts/summary"

With a login token

For an interactive script, sign in with POST /api/v1/login. The body takes userid (your email address) and password; the answer's Authorization field is the token to send as a Bearer token. Tokens expire after a while, and a user with multi-factor sign-in gets {"mfa_required": true, "pending_token": "..."} instead of a token, so prefer an API key for anything unattended.

TOKEN=$(curl -s -X POST -H "Content-Type: application/json" \
  -d '{"userid": "you@example.com", "password": "your-password"}' \
  "$SYSMANAGE_URL/api/v1/login" | jq -r '.Authorization')
curl -s -H "Authorization: Bearer $TOKEN" "$SYSMANAGE_URL/api/v1/hosts/summary"

A login token can also create an API key: POST /api/v1/api-keys with {"name": "nightly-report"} returns the key in its key field. An API key cannot be used to create another key.

If the server's certificate comes from a private CA, tell each client about it: curl --cacert ca.pem, requests.get(..., verify="ca.pem"), or add the CA to the Windows certificate store for PowerShell.

The Python and PowerShell recipes below start from this setup:

# Python
import os, requests
BASE = os.environ.get("SYSMANAGE_URL", "https://sysmanage.example.com") + "/api/v1"
s = requests.Session()
s.headers["Authorization"] = "Bearer " + os.environ["SYSMANAGE_API_KEY"]
# PowerShell
$Base = "https://sysmanage.example.com/api/v1"
$Headers = @{ Authorization = "Bearer $env:SYSMANAGE_API_KEY" }

List hosts and their status

GET /api/v1/hosts returns every host as a list. Useful fields: id, fqdn, status (up or down), approval_status (pending, approved, rejected or revoked), platform, platform_release, last_access, agent_version, reboot_required and tags. GET /api/v1/hosts/summary returns just the counts.

Bash

curl -s -H "Authorization: Bearer $SYSMANAGE_API_KEY" "$SYSMANAGE_URL/api/v1/hosts" |
  jq -r '.[] | [.fqdn, .status, .approval_status, .platform, .platform_release, .last_access] | @tsv'

Python

for h in s.get(f"{BASE}/hosts").json():
    print(h["fqdn"], h["status"], h["approval_status"], h["platform"], h["last_access"], sep="\t")

PowerShell

Invoke-RestMethod -Uri "$Base/hosts" -Headers $Headers |
  Select-Object fqdn, status, approval_status, platform, last_access | Format-Table

Find hosts with pending security updates

Each host in GET /api/v1/hosts carries security_updates_count, system_updates_count and total_updates_count. For the packages themselves, GET /api/v1/updates/HOST-ID?security_only=true returns updates, each with package_name, current_version, available_version and package_manager. Across the whole fleet, GET /api/v1/updates/?security_only=true (note the slash) pages with limit and offset.

Bash

curl -s -H "Authorization: Bearer $SYSMANAGE_API_KEY" "$SYSMANAGE_URL/api/v1/hosts" |
  jq -r '.[] | select(.security_updates_count > 0) | [.id, .fqdn, .security_updates_count] | @tsv'

# The packages waiting on one host
curl -s -H "Authorization: Bearer $SYSMANAGE_API_KEY" \
  "$SYSMANAGE_URL/api/v1/updates/HOST-ID?security_only=true" |
  jq -r '.updates[] | [.package_name, .current_version, .available_version] | @tsv'

Python

for h in s.get(f"{BASE}/hosts").json():
    if h["security_updates_count"] > 0:
        ups = s.get(f"{BASE}/updates/{h['id']}", params={"security_only": "true"}).json()
        names = ", ".join(u["package_name"] for u in ups["updates"])
        print(f"{h['fqdn']}: {h['security_updates_count']} ({names})")

PowerShell

Invoke-RestMethod -Uri "$Base/hosts" -Headers $Headers |
  Where-Object { $_.security_updates_count -gt 0 } |
  Select-Object id, fqdn, security_updates_count

Approve a pending host

PUT /api/v1/host/HOST-ID/approve, with no body. The key or token must belong to a user in SysManage's database with the Approve Host Registration role: the recovery account is refused with 401 "User not found.", and a user without the role gets 403. A host that is not pending gets 400 "Host is not in pending status".

Bash

curl -s -X PUT -H "Authorization: Bearer $SYSMANAGE_API_KEY" \
  "$SYSMANAGE_URL/api/v1/host/HOST-ID/approve" | jq '{fqdn, approval_status}'

Python

for h in s.get(f"{BASE}/hosts").json():
    if h["approval_status"] == "pending":
        r = s.put(f"{BASE}/host/{h['id']}/approve")
        print(h["fqdn"], r.status_code)

PowerShell

Invoke-RestMethod -Method Put -Uri "$Base/host/HOST-ID/approve" -Headers $Headers

Install a package on one host

POST /api/v1/packages/install/HOST-ID with package_names (a list) and requested_by (required; free text recorded with the request, such as the script's name). The agent picks the package manager. The answer has success, message and request_id. It needs the Add Package role and an approved, active host; a maintenance window can hold the installation until it opens.

Follow it with GET /api/v1/packages/installation-history/HOST-ID, which returns installations, newest first, each with request_id, status (pending, in_progress, completed or failed), package_names, requested_at, completed_at and installation_log.

Bash

REQ=$(curl -s -X POST -H "Authorization: Bearer $SYSMANAGE_API_KEY" -H "Content-Type: application/json" \
  -d '{"package_names": ["tree"], "requested_by": "install-tree.sh"}' \
  "$SYSMANAGE_URL/api/v1/packages/install/HOST-ID" | jq -r '.request_id')

# Poll until the agent reports back
until STATUS=$(curl -s -H "Authorization: Bearer $SYSMANAGE_API_KEY" \
    "$SYSMANAGE_URL/api/v1/packages/installation-history/HOST-ID" |
    jq -r --arg r "$REQ" '.installations[] | select(.request_id == $r) | .status');
    [ "$STATUS" = completed ] || [ "$STATUS" = failed ]; do sleep 10; done
echo "$STATUS"

Python

import time
host = "HOST-ID"
req = s.post(f"{BASE}/packages/install/{host}",
             json={"package_names": ["tree"], "requested_by": "install_tree.py"}).json()["request_id"]
while True:
    hist = s.get(f"{BASE}/packages/installation-history/{host}").json()["installations"]
    item = next(i for i in hist if i["request_id"] == req)
    if item["status"] in ("completed", "failed"):
        print(item["status"], item["installation_log"])
        break
    time.sleep(10)

PowerShell

$Body = @{ package_names = @("tree"); requested_by = "Install-Tree.ps1" } | ConvertTo-Json
$Req = Invoke-RestMethod -Method Post -Uri "$Base/packages/install/HOST-ID" -Headers $Headers `
  -ContentType "application/json" -Body $Body
do {
  Start-Sleep -Seconds 10
  $Item = (Invoke-RestMethod -Uri "$Base/packages/installation-history/HOST-ID" -Headers $Headers).installations |
    Where-Object request_id -eq $Req.request_id
} until ($Item.status -in "completed", "failed")
$Item.status

Export the audit log

GET /api/v1/audit-log/export returns the audit log as a file. fmt is csv (the default) or pdf; json, cef and leef need Professional and answer 402 without it. The filters are the same as the audit log viewer's: start_date and end_date (ISO 8601, UTC), user_id, action_type (for example UPDATE or EXECUTE), entity_type (for example host or package), result (SUCCESS, FAILURE or PENDING), category, entry_type and search. Without dates the export covers the whole log. It needs the View Audit Log role.

GET /api/v1/audit-log/list takes the same filters as JSON, with limit (up to 1000) and offset; it returns total and entries, and without dates it covers only the last four hours. Servers before 3.12.1.7 answer the export with 400 "Invalid audit log ID format"; on those, page through the list instead, as in the second Bash example.

Bash

curl -s -G -H "Authorization: Bearer $SYSMANAGE_API_KEY" -o audit-2026-10.csv \
  --data-urlencode "fmt=csv" \
  --data-urlencode "start_date=2026-10-01T00:00:00" --data-urlencode "end_date=2026-11-01T00:00:00" \
  "$SYSMANAGE_URL/api/v1/audit-log/export"

# The same month as JSON lines, from the list endpoint
offset=0
while :; do
  page=$(curl -s -G -H "Authorization: Bearer $SYSMANAGE_API_KEY" \
    --data-urlencode "start_date=2026-10-01T00:00:00" --data-urlencode "end_date=2026-11-01T00:00:00" \
    --data-urlencode "limit=1000" --data-urlencode "offset=$offset" \
    "$SYSMANAGE_URL/api/v1/audit-log/list")
  echo "$page" | jq -c '.entries[]'
  [ "$(echo "$page" | jq '.entries | length')" -lt 1000 ] && break
  offset=$((offset + 1000))
done > audit-2026-10.jsonl

Python

params = {"fmt": "csv", "start_date": "2026-10-01T00:00:00", "end_date": "2026-11-01T00:00:00"}
r = s.get(f"{BASE}/audit-log/export", params=params)
r.raise_for_status()
open("audit-2026-10.csv", "wb").write(r.content)

PowerShell

$Q = "fmt=csv&start_date=2026-10-01T00:00:00&end_date=2026-11-01T00:00:00"
Invoke-WebRequest -Uri "$Base/audit-log/export?$Q" -Headers $Headers -OutFile audit-2026-10.csv

When a call fails

AnswerWhat it means
401The key or token is missing, revoked or expired, or it belongs to the recovery account.
403The user lacks the role the call needs; the detail names it.
402The feature needs a higher edition than the server's license.
422The request does not match the expected shape, for example a malformed host ID or a missing field; the detail says which.
