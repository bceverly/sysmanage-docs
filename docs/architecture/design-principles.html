Design Principles

The rules SysManage is built by. Each one is a rule the code follows today, with where it shows.

1. Agents dial out; one door in

Managed hosts open no port. Every agent connects out to the server over 443 and keeps one WebSocket open, falling back to HTTP polling only when the network will not carry a WebSocket. On the server, nginx is the only network-facing listener on every platform; the application and OpenBAO listen on the loopback address only. One hardened entry point is easier to reason about than a listener per component.

2. A host is its credential, not its name

Host names are public, so they prove nothing. An agent proves which host it is with the credential it received when it registered; the server hands that credential only to the registration that created the host, and once a host has proven it, the server refuses that host to anyone who cannot. Data an agent sends, and commands it receives, are limited to its own host.

3. The database is the queue

Messages between the server and an agent are stored before they are acted on: in a table in the server's database on one side and in a local SQLite database on the agent on the other. Commands are acknowledged, retried with backoff and run once even if sent twice. There is no separate broker to run, size or lose messages in; the worker processes coordinate through PostgreSQL. See Message Flow and Queuing.

4. Nothing arrives all at once

A fleet that restarts together must not retry, report or get pushed to together. The agents wait a random time before reconnecting (full jitter, wider after the server closes connections on purpose); their timers are jittered; they send a report only when it has changed; a newly connected agent spreads its first reports over a window the server sizes from the work it already has; fleet-wide pushes such as antivirus deployment go out in waves of at most 250 hosts per database; and right after a restart the server marks no host down until the fleet has had time to come back.

5. One process or many, the same answers

The server runs as several worker processes, and running more of them must never change what it does. Work for the whole server runs only in the leader, chosen with a PostgreSQL advisory lock; one host's messages are processed by one worker at a time, under that host's lock; and retries are claimed with a single conditional update, so no message is retried twice.

6. Open core, licensed engines behind seams

The open-source server is complete on its own. Licensed features are compiled engines that plug into defined seams, are verified by signature before they load, and are simply absent without a license. A license that lapses never holds anyone's safety hostage: restoring encrypted backups and exporting their keys stay in the open-source server.

7. Schema changes expand first, contract later

The same running server serves databases on both sides of a migration while they are migrated one by one, so a release only adds to the schema; removing or renaming waits for a later release, and a lint check enforces it. See Database Migrations.

8. Claim only what was measured

Capacity is proven with a scale harness that restarts a real server under thousands of simulated agents, and only the numbers it proved are published -- 10,000 agents on one laptop, 20,000 across 20 tenants on one desktop. What has not been measured, such as 50,000 agents, is labeled as not proven. See Performance and Scale.

9. Every platform, every language

The agent runs on Windows, Linux, macOS, FreeBSD, OpenBSD and NetBSD, using each system's own tools rather than assuming one of them, and it is tested on each. Every string a user reads -- in the console, in the server's messages and in these documents -- is externalized and translated into 14 languages.
