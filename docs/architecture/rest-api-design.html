REST API Design

The web interface and any automation you write use the same JSON-over-HTTPS API. It is built with FastAPI and reached through nginx on port 443 under /api/. This page covers the conventions every endpoint shares; the endpoints themselves are in the API reference.

Versioning

Every feature endpoint is served under /api/v1 -- for example /api/v1/login or /api/v1/api-keys. The older unversioned /api/... aliases for these endpoints have been retired, so a call must use the /api/v1 path. /api/v2 is reserved for a future, deliberately introduced breaking version and is not served today. Endpoints provided by licensed Pro+ engines are mounted under /api/v1 as well.

A few surfaces are kept unversioned on purpose, because something outside the server's release cycle depends on the exact path:

  • Agent communication -- /api/agent/* (authentication, the WebSocket and the HTTP poll), /api/host/register and the agent-facing /api/certificates/* endpoints. Agents of different versions talk to one server, so these paths never move.
  • Multi-factor sign-in -- /api/auth/mfa/* and /api/settings/mfa.
  • External identity provider callbacks -- the OIDC and SAML start, callback, ACS and metadata URLs under /api/auth/, which are configured in the identity provider.
  • SCIM provisioning -- /api/scim/v2/<provider>/Users; the v2 there is the SCIM protocol's version, not SysManage's.
  • Health checks -- /api/health (liveness) and /api/health/db (a real database round trip, answering 503 when the database is unreachable).

Authentication

Almost every endpoint needs a credential in the Authorization: Bearer <credential> header. Two kinds are accepted, and every endpoint that takes one takes the other:

  • A JWT from POST /api/v1/login, which takes a userid (an email address) and a password and answers {"Authorization": "<token>"}. The token lasts security.jwt_auth_timeout seconds (3600 by default). Login also sets an HTTP-only refresh_token cookie (86400 seconds by default), which POST /api/v1/refresh exchanges for a new token; POST /api/v1/logout ends the session. A user with multi-factor authentication gets mfa_required and a short-lived pending token instead, which is completed at /api/auth/mfa/verify.
  • An API key for automation, created under /api/v1/api-keys. Keys start with smk_, are shown once when created and are stored only as a SHA-256 hash. A key acts as the user who owns it, with that user's permissions.

Repeated failed sign-ins lock the account: 5 failures by default (security.max_failed_logins), for 15 minutes (security.account_lockout_duration). A missing, malformed or expired credential is refused with 401 or 403. With multi-tenancy enabled, the JWT carries the active tenant, and an API key carries its own tenant pin. More in Authentication.

curl -H "Authorization: Bearer smk_..." \
  https://sysmanage.example.com\
/api/v1/hosts

Errors

Errors use HTTP status codes and a JSON body with a detail field. For most errors detail is a message; for a request body or query that fails validation (422) it is FastAPI's list of the fields at fault. An unexpected server error answers 500 with a generic message, and the details go to the server log rather than to the caller. A command the target host's agent cannot run answers 409 with "reason": "unsupported_capability" and the command_type.

{"detail": "Expired token."}

Paging

Endpoints that can return long lists -- the audit log, package searches, backups, diagnostics and others -- take limit and offset query parameters. Each endpoint sets its own default and maximum; the audit log, for example, returns 100 entries by default and at most 1000. Endpoints with naturally short lists return everything.

Rate limiting

A request rate limiter is built in but off by default, because a per-address limit can throttle every user behind one proxy. An operator turns it on with api.rate_limit.enabled in sysmanage.yaml (or the SYSMANAGE_RATE_LIMIT_ENABLED environment variable) and tunes it with api.rate_limit.requests and api.rate_limit.window_seconds -- 1000 requests per 60 seconds per client by default. A client over the limit gets 429 with a Retry-After header. Agent communication (/api/agent/*), WebSockets and the health checks are never limited. Behind a reverse proxy listed in security.trusted_proxies, the client is taken from X-Forwarded-For; that header is ignored from anyone else.

Sign-in attempts and agent connection requests have their own limits, which are always on.

The OpenAPI document

FastAPI generates an OpenAPI document from the code, with interactive pages, at its default paths /openapi.json, /docs and /redoc on the application itself. The bundled nginx configuration forwards only /api/ and /ws to the application, so these are reachable on the server at http://127.0.0.1:8080/docs, not through port 443.
