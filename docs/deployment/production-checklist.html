Production Readiness Checklist

Go through this list before a SysManage server carries a real fleet, and again after any large change. Each item is one line; the link goes to the page with the details.

Capacity

  • Give the server about 3 CPU cores and 4 GB of memory per 10,000 agents, plus the database -- Scaling.
  • Keep to about 2,500 agents per worker; the server picks the worker count for its machine unless api.workers is set -- Scaling.
  • Set PostgreSQL's max_connections from the formula, and look for "Database pool reduced to fit the server" in the log after a restart -- Scaling.

Database

  • Run PostgreSQL 12 or newer, with its own machine past about 20,000 agents -- Scaling.
  • For a database that survives losing its machine, run an HA PostgreSQL cluster -- PostgreSQL High Availability.
  • Do not put a transaction-mode pooler such as PgBouncer in front of it: the server holds session-level advisory locks -- Scaling.

TLS and network exposure

  • Install a real certificate for the server's name at /etc/sysmanage/tls/server.crt and server.key; nginx will not start without one, and agents verify it -- Installation.
  • Only nginx listens on the network, on 443 (80 only redirects); the backend stays on 127.0.0.1:8080 and OpenBAO on 127.0.0.1:8200 -- Network Security.
  • Leave api.host on localhost and dev_mode out of the configuration; the server warns at startup if the API is bound to a public address -- Configuration.
  • Allow inbound 443 (and 80 for the redirect) and nothing else; agents need only outbound 443 to the server -- Network Security.

Accounts and email

  • Configure SMTP so invitations and password resets reach people -- Settings, Administrator Invitations.
  • Create your own administrators, then remove admin_userid and admin_password from /etc/sysmanage.yaml and restart -- Installation.
  • Turn on multi-factor sign-in for administrators -- Authentication.

Backups and recovery

  • Back up the databases, OpenBAO, the configuration, the agents' CA and the TLS certificate on a schedule, off the machine -- Server Backup and Recovery.
  • Encrypt those backups and limit who can read them: they carry the OpenBAO unseal key and the database password -- Server Backup and Recovery.
  • Restore one onto a test machine and time it before you need it -- Server Backup and Recovery.

Monitoring, logs and time

  • Poll /api/health for liveness and /api/health/db (HTTP 503 when the database is unreachable; not for high-frequency polling) for readiness -- Monitoring.
  • Watch the server from outside with the production canary -- Best-Practice Deployment.
  • Professional+: alert when /api/v1/license/module-compat lists an engine that cannot load -- Maintenance.
  • The server log is /var/log/sysmanage/backend.log, rotated at midnight with 14 kept; forward it if you need more -- Logging Configuration.
  • Keep the server's and the database's clocks synchronized; the server measures every host's clock against its own -- Time Sync.

Upgrades, license and availability

  • Plan upgrades: back up, upgrade, migrate, restart, and know how to roll back -- Upgrading and Rolling Back.
  • Professional+: put the license key in license.key, let the server reach the license server for engine downloads, and keep the license in your backups -- Professional+.
  • Multi-tenancy: OpenBAO must be running and unsealed for the server and for every migration -- Multi-Tenancy.
  • Plan for one active server: several SysManage servers for failover are not available yet (planned); while it restarts, agents wait and reconnect -- Maintenance.
