Onboard a Hundred Hosts

Bring a batch of machines under management in one pass: install the agent everywhere with the same configuration, approve the hosts without clicking each one, organize them with tags, and prove that none is missing.

When to use it

Use it for a rollout, a data center migration or an acquisition -- any time more hosts arrive than you want to set up one at a time. For a first look at a few hosts, Your First Mixed Fleet is shorter.

What you need

  • A running server with a TLS certificate the hosts trust, reachable from every host on port 443. Check its size against the fleet in the Scaling Guide.
  • A list of the hosts, and a way to run commands on all of them: Ansible, another configuration-management tool, or your imaging process.
  • Community covers installing, bulk approval, tags and asset tags.
  • Enterprise adds registration keys, which approve hosts automatically as they enroll (step 1).
  • A user created in SysManage with the Approve Host Registration role, Edit Tags for tags and Manage Asset Tags for asset tags. The recovery account from sysmanage.yaml cannot approve hosts.

1. Create a registration key (Enterprise)

Open Administration > Settings > Access Groups. Under Registration Keys choose Add Key, give it a Name, tick Auto-approve registrations using this key, and set Max Uses (blank = unlimited) to the size of the batch and an Expires At date a little after the rollout ends. Choose Generate Key. The key is shown once, under Registration Key Created; copy it then. Picking an Access Group also places every host in that group.

Without Enterprise, skip this step: the hosts arrive as Approval Needed and you approve them in bulk in step 4.

2. Prepare one agent configuration

Every host gets the same file. On Linux it is /etc/sysmanage-agent.yaml; on FreeBSD /usr/local/etc/sysmanage-agent/config.yaml. The agent configuration reference lists the paths on the other platforms. The settings that matter here:

server:
  url: "https://sysmanage.example.com"
  # Only if the server's certificate comes from a private CA:
  # ca_bundle: "/etc/ssl/certs/sysmanage-ca.pem"

security:
  # Enterprise only: the key from step 1
  registration_key: "paste-the-key-here"

Use the server's DNS name in url, never its IP address: if the server is ever replaced, a name lets you move it without touching a single agent. registration_key belongs under security, not under server.

3. Install the agents

Install the agent package on each host, put the configuration file in place, then start the agent. The commands for every platform are in the Agent Installation Guide; Deploying the Agent to Many Hosts has an Ansible playbook that does all three steps and suggests a phased rollout. On Ubuntu, for example:

sudo add-apt-repository -y ppa:bceverly/sysmanage-agent
sudo apt-get update
sudo apt-get install -y sysmanage-agent
sudo install -m 640 -o sysmanage-agent -g sysmanage-agent sysmanage-agent.yaml /etc/sysmanage-agent.yaml
sudo systemctl restart sysmanage-agent

Start with five or ten hosts, check that they arrive (step 6), then run the rest.

4. Approve the hosts

With a registration key, there is nothing to do: each host is approved as it registers, and the audit log records "Host '...' enrolled via registration key '...'".

Without one, open Fleet > Hosts. New hosts show Approval Needed in the Status column. Tick the box at the top of the list; the foot of the list shows how many hosts are selected. Choose Approve Selected: of the selected hosts, the ones waiting for approval are approved and the rest are left alone. To approve every pending host from a script instead:

API=https://sysmanage.example.com/api/v1
AUTH="Authorization: Bearer $SYSMANAGE_API_KEY"
curl -s -H "$AUTH" "$API/hosts" | jq -r '.[] | select(.approval_status == "pending") | .id' |
while read -r id; do
  curl -s -o /dev/null -w "%{http_code} $id\n" -X PUT -H "$AUTH" "$API/host/$id/approve"
done

Each line should start with 200. The key or token must belong to a user with the Approve Host Registration role. More API recipes, in Python and PowerShell too, are in API Examples.

5. Organize them

  • Tags group hosts by role, site or patch wave, and maintenance windows can apply to a tag. Create them under Administration > Settings > Tags > Add Tag; add one to a host with Add Tag on the host's Info tab. For a hundred hosts, use the API: POST /api/v1/hosts/{host_id}/tags/{tag_id} for each host (the tag IDs come from GET /api/v1/tags).
  • Asset tags label the machine itself, and stay with it when it is reinstalled. Under Administration > Settings > Asset Tags, set the naming scheme, then use Import CSV... with an asset_tag column and a system_uuid or system_serial column. The preview shows what each row will do before anything is written; Export CSV gives back the result. A tag for a machine that has not arrived yet waits for it.
asset_tag,system_serial
IT-00101,5CG1234ABC
IT-00102,5CG1235ABC

6. Check that every host arrived

  • On Fleet > Hosts, the count at the foot of the list is the number of hosts. Every new host should be Up and no longer Approval Needed. Filter by Tags shows one group at a time, and Untagged only shows the machines that still have no asset tag.
  • For a number to compare with your list, ask the server for the summary:
curl -s -H "Authorization: Bearer $SYSMANAGE_API_KEY" https://sysmanage.example.com/api/v1/hosts/summary
# {"total": 104, "approved": 104, "approved_up": 104, "approved_down": 0, "reboot_required": 3}

# Which names from your list are missing?
curl -s -H "Authorization: Bearer $SYSMANAGE_API_KEY" https://sysmanage.example.com/api/v1/hosts |
  jq -r '.[].fqdn' | sort > arrived.txt
sort hosts.txt | comm -23 - arrived.txt

If a step fails

What you seeWhat to do
A host never appearsOn the host, look for "Connected to server successfully" in the agent log. If the log says certificate verify failed, the host does not trust the server's certificate: set ca_bundle. If it cannot connect at all, check DNS and port 443 with curl https://sysmanage.example.com/api/health.
Registration is refused with "Invalid or expired registration key"The key was revoked, has expired or has reached its Max Uses. The server does not say which. Check the key under Administration > Settings > Access Groups, or create a new one and update the configuration.
Hosts with a key still show Approval NeededThe key does not have auto-approval turned on, or registration_key is not under security in the file. Approve these hosts as in step 4.
Approve Selected does nothing, or the API answers 401 "User not found."You are signed in as the recovery account. Sign in as a user created in SysManage.
The API answers 403 "Permission denied: APPROVE_HOST_REGISTRATION role required"The user behind the key lacks the Approve Host Registration role. Grant it under Administration > Users.
Two hosts share one nameCloned machines often keep the same hostname. Give each machine its own hostname before installing the agent.
