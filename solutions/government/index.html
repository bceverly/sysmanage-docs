What government infrastructure actually demands

Regulated and mission environments share a hard set of non-negotiables: isolation from the public internet, defensible compliance evidence, coverage for the operating systems that actually run critical systems, and a stack you can inspect rather than take on faith. SysManage was designed around these constraints, not adapted to them after the fact.

🔒

Fully air-gapped operation

Run the entire platform on networks with no internet route at all (Enterprise) -- single-tenant appliance, local secret storage, and offline content delivery. See the air-gapped deployment model.

📋

FIPS mode and compliance evidence

See which hosts run in FIPS mode and switch it on Ubuntu (with Ubuntu Pro), the RHEL family and Windows (Enterprise), and run CIS and DISA STIG checks on Linux (Professional). The results help you produce the evidence your assessors ask for; SysManage itself is not FIPS 140 validated, FedRAMP authorized or covered by an ATO.

🐡

BSD support in the same console

FreeBSD, OpenBSD, and NetBSD run a great deal of defense, networking, and critical infrastructure -- and SysManage manages them from the same agent and console as Windows, Linux, and macOS. The supported platforms page lists what each one can and cannot do.

🔍

Open-source core you can audit

The core is AGPLv3 and fully inspectable -- no black boxes. Security teams and accreditors can read the code that runs on their networks.

🏛️

On-premises & sovereign

Your hardware, your data, your network. SysManage runs entirely under your control; the license is checked locally, and nothing depends on a vendor cloud.

🛡️

Strong access control

Role-based access control, multi-factor sign-in, administrator approval of every new host, and TLS 1.2 or later between agents and server keep authority scoped and every action in the audit log.

Compliance evidence you can report on

Accreditation lives and dies on evidence. SysManage runs CIS and DISA STIG checks on your Linux hosts (Professional), records every action in the audit log, and turns the results into reports you can hand to an assessor. For Windows, macOS and the BSDs it reports patch state, vulnerabilities, and firewall and antivirus status rather than benchmark checks. It helps you produce evidence against the standards you're held to; it does not certify or accredit anything.

  • CIS and DISA STIG checks on Linux -- a focused set of about 50 rules
  • Evidence and an audit trail you can report from directly
  • Fleet FIPS posture, with FIPS mode switched on Ubuntu, the RHEL family and Windows (Enterprise)

The platforms defense actually runs

A great deal of defense, networking, and critical infrastructure runs on the BSDs -- and most endpoint-management products do not manage them at all. SysManage puts FreeBSD, OpenBSD, and NetBSD on the same console as Windows, Linux, and macOS: inventory and scripts on all three, vulnerability scanning on all three (OpenBSD: the base system), updates applied on FreeBSD and to OpenBSD's base system, and NetBSD updates detected.

  • FreeBSD, OpenBSD, and NetBSD in the same console as every other platform
  • One console for all six operating systems
  • Per-platform differences stated plainly on the supported platforms page

Auditable by design

Because the core is open source under AGPLv3, security teams and accreditors can read the code rather than trust a vendor's word for what it does. Combined with on-premises and air-gapped deployment -- where the license is checked locally with no time limit and the platform needs no route to the internet -- that adds up to a stronger trust posture than a closed, cloud-hosted tool can offer.
